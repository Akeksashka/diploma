# Tooling for collection, analysis and visualization

Access date for every URL in this note: 2026-10-17. Standalone note, written ahead of the indicator-selection approval gate at the user's explicit request; it does not depend on the indicator list. Companion to `docs/research/data-sources-g20-eu-cross-country.md` (source assessment, not repeated here). This is an assessment, not a design decision; no architecture, no code.

Evidence labels:
- [PYPI] = read from the package's PyPI JSON page (`https://pypi.org/pypi/<name>/json`), 2026-10-17. Gives latest version, `requires_python`, licence and classifiers. For most packages the fetch was truncated before the release timestamp, so the upload date is only given where it was visible; otherwise "date not seen".
- [DOC] = stated on a fetched primary documentation page.
- [SEARCH] = web-search snippet or forum post; confirm against a primary page.
- [UNVERIFIED] = analyst knowledge or not checked.
- [CRAN] = read from the package's CRAN landing page (`https://cran.r-project.org/web/packages/<name>/index.html`), 2026-10-17 (addendum only).

"Py3.12" below means the 3.12 classifier or an unrestricted `requires_python` that admits 3.12 is present on PyPI. It does not mean we ran the package.

## Question / scope

Which free (preferably open-source) Python 3.12 tools can (1) collect and parse data from the sources already assessed (Eurostat, OECD, IMF, BIS, ECB, World Bank, ILOSTAT, FRED/ALFRED, SDMX/JSON-stat, bulk CSV/XLSX, HTML), (2) support analysis, forecasting and quality validation, and (3) visualize and publish results, including hosted free tiers for dashboards, orchestration/scheduling and notebooks? For each: maintenance status, licence, free-tier limits, and fit to the project conventions in `CLAUDE.md` (immutable raw data with URL + fetch timestamp + hash; vintage preservation; series metadata: source, id, frequency, unit, SA, vintage). Out of scope: choosing a stack, storage layout, code.

### G. Storage options (free tiers) for time series with vintages

Fit to the vintage convention (analyst view, applies to every row): a vintage-preserving store needs append-only rows keyed by series id + observation period + knowledge/vintage date (bitemporal: valid time = the period the value describes; transaction/knowledge time = when the value was published or fetched). None of the services below provides this natively; each would carry it as a key convention, and none replaces the raw-file archive (URL, timestamp, hash) required by `CLAUDE.md`.

Mixed Python + R pitfalls (analyst view unless cited):
- Two toolchains in CI and locally: R (renv lockfile / `DESCRIPTION`) beside Python (3.12 pin); two sets of CVE/version updates; slower CI (R package installs, wasm availability) [UNVERIFIED timing].
- Hand-off format: both need one interchange format (Parquet or CSV) with identical dtypes, missing-value and date conventions; period types differ between pandas (Period/Timestamp) and tsibble (yearmonth, yearquarter) [UNVERIFIED mapping]. Vintage columns and series metadata (source, id, frequency, unit, SA) would need to survive both.
- Duplicate collection logic: SDMX clients differ (sdmx1 vs rsdmx/readsdmx); if collection is Python and analysis is R, R should not re-fetch.
- Testing and linting conventions in `CLAUDE.md` are Python-specific (`ruff`, `pytest`, `tests/unit`); R would need its own (e.g. testthat, lintr) [UNVERIFIED tool choice].
- Embedding R in Python (or the reverse) via bridge packages adds a dependency on matching R/Python installs [UNVERIFIED, not researched].
- Licences: GPL-3 R packages vs Apache/MIT Python ones; only relevant if code is combined and redistributed.
- Python 3.12 is stated in `CLAUDE.md` ("Global engineering conventions", and the repository map lists `src/macro_monitor/` with Python modules). Introducing R, even for analysis only, conflicts with that convention and the Python-oriented phase-4 agent/tooling. This note flags the conflict and does not resolve it; an ADR or CLAUDE.md update would be needed if R is adopted (per the Implementation rule that design changes need an approved ADR).

## Findings (each with citation: URL, access date 2026-10-17)

1. pandasdmx is not usable on Python 3.12: `requires_python >=3.9.6,<3.12`, last release 1.10.0 on 2023-02-25 (https://pypi.org/pypi/pandasdmx/json). Its maintained fork `sdmx1` (2.27.0, `>=3.10`, classifiers 3.12-3.14; https://pypi.org/pypi/sdmx1/json) is the viable SDMX client. It ships source definitions for ECB, Eurostat (incl. Comext), BIS, ILO, IMF (2.1 and 3.0), OECD, World Bank, and national offices, with documented per-source quirks (https://sdmx1.readthedocs.io/en/latest/sources.html).
2. IMF access is in flux in the tooling too: sdmx1 flags IMF sources as beta/limited ("IMF_DATA3 ... limited support") and the legacy `dataservices.imf.org` as an SDMX 2.0 service without tests (https://sdmx1.readthedocs.io/en/latest/sources.html). A dedicated `imfp` client (2.1.0, 2026-09-24) targets the new SDMX 3.0 API (https://pypi.org/pypi/imfp/json). Neither changes the IMF terms limiting automated bulk downloads (companion note, F2).
3. Client libraries are not a vintage solution. Only FRED/ALFRED has an official vintage API (companion note F4); the `fredapi` wrapper is stale (0.5.2, 2024-05-05, no `requires_python`; https://pypi.org/pypi/fredapi/json), so direct REST use is a realistic alternative. World Bank `wbgapi` offers WDI Archives (db 57) for older WDI versions (https://pypi.org/project/wbgapi/). DBnomics exposes dataset "releases" such as `WEO:2019-04` (https://docs.db.nomics.world/web-api/) but docs do not say all past releases are served.
4. wbgapi is maintained (1.0.14, 2026-02-27, MIT) but has no caching; its docs recommend requests-cache (https://pypi.org/project/wbgapi/). Its PyPI metadata does not declare 3.12 explicitly.
5. Conditional requests: requests-cache automatically sends If-None-Match/If-Modified-Since when a validator exists, supports stale-if-error, and honours response Cache-Control only if enabled (https://requests-cache.readthedocs.io/en/stable/user_guide/headers.html). hishel (1.4.0, 2026-09-16) provides RFC 9111 caching and revalidation for httpx (https://hishel.com/, https://pypi.org/pypi/hishel/json). Whether each source emits ETag/Last-Modified is untested (see Risks). A cache is not the immutable raw archive required by `CLAUDE.md`; it reduces repeat traffic only.
6. Eurostat specifics that affect tooling: a first request can return an asynchronous status and the same URL should be retried after a few minutes; `lastNObservations` does not reduce extraction size, so large requests can fail with `EXTRACTION_TOO_BIG` unless a time filter such as `c[TIME_PERIOD]=ge:2024` is added; long URLs cause HTTP 400 (https://ec.europa.eu/eurostat/web/user-guides/data-browser/api-data-access/api-faq). The official guide lists separate Statistics, SDMX 2.1, SDMX 3.0 and Catalogue APIs plus a Comext base (https://ec.europa.eu/eurostat/web/user-guides/data-browser/api-data-access/api-getting-started, via search snippet). No numeric rate limit found.
7. Scheduling: for a monthly day-1 refresh, GitHub Actions is free for public repos and gives 2,000 min/month on private repos; scheduled runs can be delayed or dropped at high load, only run from the default branch, and are auto-disabled in public repos after 60 days without activity (https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows). Runner storage is ephemeral, so results must be committed or uploaded elsewhere (artifact quota is 500 MB on Free; https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions).
8. Orchestrators: Prefect (3.8.8, Apache-2.0) has a free Cloud "Hobby" tier (2 users, 5 deployments, 7-day run retention) (https://www.prefect.io/pricing). Dagster (1.13.26, Apache-2.0) has no free hosted tier, only a 30-day trial then $10/month Solo (https://dagster.io/pricing); OSS is self-host. Airflow 3.3.2 (Apache-2.0) is the heaviest to run. All three declare Python 3.12 (https://pypi.org/pypi/prefect/json, /dagster/json, /apache-airflow/json). For one monthly job a full orchestrator is likely more machinery than needed [analyst view]; compare against cron/Actions at design.
9. Storage: Parquet via pyarrow (26.0.0) and DuckDB (1.5.6, MIT) both declare Python 3.12 (https://pypi.org/pypi/pyarrow/json, https://pypi.org/pypi/duckdb/json). pandas is now 3.0.6 (`>=3.11`) and polars 2.0.0 (3.10-3.13): downstream library compatibility with pandas 3 was not checked.
10. Nowcasting: statsmodels 0.15.0 `DynamicFactorMQ` implements the Bańbura-Modugno mixed monthly/quarterly dynamic factor model with EM estimation, arbitrary missing entries, nowcasting and a `news` method on results (https://www.statsmodels.org/stable/generated/statsmodels.tsa.statespace.dynamic_factor_mq.DynamicFactorMQ.html). VAR/SARIMAX/state-space are in the same package (https://pypi.org/pypi/statsmodels/json, `>=3.10`, 3.12 listed). I found no separate maintained Python nowcasting package in this session: [UNVERIFIED, not searched].
11. Seasonal adjustment: statsmodels wraps the Census X-13ARIMA-SEATS binary via subprocess (found on PATH or `X13PATH`) (https://www.statsmodels.org/stable/generated/statsmodels.tsa.x13.x13_arima_analysis.html). Census distributes Windows and Linux/Unix binaries; its page states no licence (https://www.census.gov/data/software/x13as.html). So SA requires an external binary and, on macOS, a self-build or alternative [UNVERIFIED]. Statsmodels STL is binary-free but is a different method.
12. Forecasting libraries all declare 3.12: sktime 1.2.0 (BSD-3), statsforecast 2.1.1 (Apache-2.0), darts 0.48.1 (Apache-2.0, 3.11-3.13 only), Prophet 1.5.0 (MIT, released 2026-10-05) (PyPI JSON pages cited in tables). No accuracy comparison was performed; method choice for macro data (short monthly/annual series, structural breaks, revisions) is a design/analysis question.
13. Validation: pandera 0.34.1 (MIT, 3.10-3.14) is a lightweight dataframe schema checker; Great Expectations 1.24.0 (Apache-2.0, 3.10-3.14) is heavier with data docs (https://pypi.org/pypi/pandera/json, https://pypi.org/pypi/great-expectations/json). Fit to "every series carries source, id, frequency, unit, SA, vintage" is feasible with either via column/metadata checks [analyst view].
14. Visualization stack: Plotly 7.1.0 (MIT, 3.8-3.13), Altair 6.3.0 (BSD, `>=3.11`, to 3.14), Matplotlib 3.11.2 (3.11-3.14). Apps: Streamlit 1.66.0 (Apache-2.0), Dash 4.4.1 (MIT, classifiers to 3.12), Panel 1.9.4 (BSD), Superset 6.1.0 (Apache-2.0, 3.10-3.12 only) (PyPI pages cited in tables).

Object/file stores: R2 free is 10 GB-month, 1M Class A / 10M Class B ops, free egress (https://developers.cloudflare.com/r2/pricing/); GitHub release assets are <2 GiB each with no total/bandwidth limit, but repo files are blocked above 100 MiB and repos should stay <1 GB (https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases, https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github); Hugging Face public dataset storage is "best-effort" free with 100 GB free private and a stated expectation of community reuse (https://huggingface.co/docs/hub/storage-limits); MotherDuck Lite is 10 GB / 10 CU-hours with pay-as-you-go beyond (https://motherduck.com/product/pricing/). Only the first two need no database server.
20. TimescaleDB: core is Apache-2.0 and the `tsl/` directory is under the Timescale License (https://raw.githubusercontent.com/timescale/timescaledb/main/LICENSE). Free cloud tier status is contradictory in the sources found; no primary pricing page was read. Low-volume monthly macro series probably do not need it [analyst view].
21. n8n: Community Edition is under the Sustainable Use License: internal business, non-commercial or personal use; redistribution only free and non-commercial; notices must be kept (https://raw.githubusercontent.com/n8n-io/n8n/master/LICENSE.md). n8n Cloud has no permanent free tier, only a trial (1,000 executions, 180 s timeout) and then EUR 20+/month (https://n8n.io/pricing/). Self-hosting needs an always-on host, and the one free host checked (Render) spins web services down after 15 min and lists no free cron/worker type (https://render.com/docs/free). So n8n cannot be run free on the web in a scheduled way on evidence found, unless hosted elsewhere (unassessed).
22. n8n's Python Code node cannot import libraries on Cloud and needs an allowlisted, custom task-runner image when self-hosted ([SEARCH] on https://docs.n8n.io/build/code-in-n8n/using-the-code-node). Community Edition lacks Git-based workflow version control (https://docs.n8n.io/hosting/community-edition-features/). GitHub Actions + Python (6 h job limit, 20 concurrent jobs on Free; https://docs.github.com/en/actions/reference/limits) can do the same fetch-hash-write job at zero cost on a public repo and keeps the logic under the repo's tests and lint conventions.
23. R: current CRAN releases include fpp3 1.0.3 (2026-02-13), forecast 9.0.2 (2026-03-18), tsibble 1.2.0 (2026-02-09), seasonal 1.11.0 (2026-09-14), eurostat 4.1.1 (2026-09-24), imf.data 0.2.0 (2026-07-06), rsdmx 0.6-5 (2025-02-27); stale ones are OECD 0.2.5 (2021-12-01), fredr 2.1.0 (2021-01-29), readsdmx 0.3.1 (2023-09-02) (CRAN landing pages in the addendum table). x13binary ships X-13 binaries for Windows and macOS (https://cran.r-project.org/web/packages/x13binary/index.html).
24. Free web homes for R, per primary docs: GitHub Actions (r-lib/actions setup-r / setup-renv; https://github.com/r-lib/actions), Quarto to GitHub Pages incl. `freeze: auto` (https://quarto.org/docs/publishing/github-pages.html), Shinylive/webR static apps limited to precompiled wasm packages (https://posit-dev.github.io/r-shinylive/), Posit Connect Cloud Free (public GitHub repos; usage-credit limits to be enforced from the first usage period on or after 2026-11-01; https://docs.posit.co/connect-cloud/user/usage.html). shinyapps.io Free figures (5 apps, 25 hours) are from a search snippet only.

## Risks / unknowns

1. Upload dates were not visible for most PyPI entries (truncated JSON); "last release" is therefore reliable only for entries with dates. Re-check with the PyPI release history before pinning. Also the PyPI "latest" for pandas 3.0.x, polars 2.0.0, pyarrow 26.0.0 are major versions; compatibility matrices (statsmodels, sktime, darts, pandera) with pandas 3 are untested.
2. No code or live endpoint was run in this session; everything is documentation/metadata. Conditional-request support (ETag, Last-Modified) per data source is untested, as are pagination and response formats.
3. imfp licence metadata is inconsistent (Apache-2.0 field vs MIT classifier); dbnomics client is AGPL-3.0-or-later, which has redistribution implications: both need confirming at design.
4. Source terms may limit tooling regardless of client choice: IMF bulk-download clause, OECD rate limits (60/hour vs 20/hour conflict), FRED terms (no replicating FRED's user experience; copyrighted series need owner permission; delete API copies on termination) (https://fred.stlouisfed.org/docs/api/terms_of_use.html), Eurostat async/size limits. Companion note carries the rest.
5. Hosted free tiers change often (Hugging Face now requires paid plans for compute Spaces; Streamlit sleep time was reportedly reduced to 12 h). Treat all limits as perishable.
6. X-13 requires an external binary; platform coverage (macOS) and licence not confirmed.
7. Not assessed: Python clients for ECB (ECB Data Portal help pages returned HTTP 503 again; sdmx1 `ECB` source exists), Fed/other central banks directly, national statistics offices, `dlt`/Singer-style ingestion frameworks, Polars-based IO packages, Marimo/Jupyter/Quarto (Quarto now only partly covered in the addendum), Observable Framework (HTTP 429), nowcasting-specific packages, Docker-based free hosts, robots.txt of scrape targets.
8. Claims about suitability ("weak fit", "heavy", "overkill") are analyst judgement, not measured.

Risks added in the addendum (2026-10-17):

9. Free-tier terms are vendor-controlled and change: Neon is now under Databricks and its agreement lets plans/pricing change on notice by continued use (https://neon.com/terms-of-service); Posit Connect Cloud Free limits begin to be enforced from 2026-11-01 (https://docs.posit.co/connect-cloud/user/usage.html). A store whose only copy of vintages sits on a free tier risks loss; the raw archive and a restorable export need a second location (design question).
10. Pausing and cold starts: Supabase Free pauses after about 1 week idle (a monthly job exceeds that); Neon cold-start latency and behaviour after long idleness were not measured; Neon/Supabase/MotherDuck deletion-after-long-inactivity rules were not found (absence of evidence).
11. "Free only" vs pay-as-you-go: MotherDuck Lite and Cloudflare R2 beyond free tier bill per use; whether a payment card is required to open an account (R2, MotherDuck compute beyond trial) was not verified.
12. Licence readings (n8n Sustainable Use License; GPL-3 R packages; TSL in TimescaleDB; x13binary "file LICENSE"; AGPL dbnomics) are plain-text readings, not legal advice; the project is assumed non-commercial and public [user constraints].
13. Several figures come from search snippets only: shinyapps.io Free limits (support page returned HTTP 403), Posit Connect Cloud Beta numbers, n8n Python Code node import rules, Neon branch archiving, TimescaleDB cloud free-tier status.
14. R package health is uneven (OECD, fredr, readsdmx not updated for 2-5 years); compatibility with current OECD, IMF and FRED interfaces was not tested. wasm availability of the forecasting stack for Shinylive was not checked.
15. Mixed-language operation (Python + R) increases CI time, dependency surface and hand-off defects; none measured. Python 3.12 convention conflict recorded in finding 25.
16. Not assessed in the addendum: other free hosts for an always-on n8n (Fly.io, Koyeb, Oracle free VM, etc.), Neon/Supabase Python driver specifics, DuckDB-WASM in-browser reads, GitHub "immutable releases"-style protections, Cloudflare R2 object versioning/lock, Quarto licence, Positron/renv details.

## User constraints (given 2026-10-17)
- No paid services: free and open-source tools or free tiers only. This rules out Dagster+ (no free tier) and any paid hosting.
- Repo will be public (GitHub Actions free; note the 60-day inactivity auto-disable of scheduled runs).
- Data refresh monthly; the visualization must be interactive for the user (inspect data, filter).
- Must run on the web (not only on the user's Mac), at no cost: collection, storage and the dashboard all need a free hosted home. (Added 2026-10-17.)
- A persistent data store is required for analysis (a static report alone is not enough). (Given 2026-10-17.)
- Strictly free: no card on file, no pay-as-you-go. This rules out MotherDuck beyond its free allowance and any service that bills past a free tier. (Given 2026-10-17.)
- Automation is the goal, not a visual workflow editor: n8n is not required. (Given 2026-10-17.)
- No preference between R and Python for analysis; CLAUDE.md's Python 3.12 convention stands unless design finds a reason to change it. (Given 2026-10-17.)
- Skip the DBnomics Python client (AGPL-3.0). Use `sdmx1` (Apache-2.0) and direct REST calls instead.

## Open questions for design

For the user:
1. Audience and interaction: is a static, monthly-refreshed report/dashboard sufficient, or is live interactive exploration required? This decides between static hosting and an always-on app.
2. Is the repository to be public or private? It changes GitHub Actions minutes (free for public repos, 2,000/month private), the 60-day scheduled-workflow auto-disable rule, and Pages availability.
3. Is any paid service acceptable (e.g. Dagster+ $10/month, Hugging Face PRO), or strictly free only?
4. Are we willing to depend on a third-party aggregator client (DBnomics, AGPL) or only first-party source APIs plus sdmx1?

For the design phase (questions only):
5. How is the raw immutable archive (URL, timestamp, content hash) kept separate from the HTTP cache so that cache expiry never alters raw files?
6. Which sources need direct REST calls rather than a client (FRED/ALFRED vintages, bulk XLSX/ZIP files) and which can go through sdmx1?
7. How will Eurostat async responses, size caps and the OECD download cap be handled in a scheduled job (retries, time filters, bulk files)?
8. Does a monthly job justify an orchestrator (Prefect/Dagster/Airflow), or are cron/GitHub Actions plus a Makefile-style runner enough? Where does state (last-seen `updated`/`UpdatedAfter`) live between ephemeral runs?
9. Parquet files only, or DuckDB as catalogue/query layer; how are vintages keyed (as-of date) and appended?
10. Is own seasonal adjustment needed at all given source-published SA series, and if so is a native X-13 binary acceptable in CI and local macOS?
11. Which forecast/nowcast methods are in scope (baseline ARIMA/ETS, VAR, mixed-frequency DFM), and how are they evaluated against revised vs real-time data?
12. Validation depth: pandera-style schema checks vs Great Expectations data docs; what checks enforce the series metadata convention?
13. Follow-up research needed: pandas 3 compatibility across the chosen stack; confirmation of Streamlit Community Cloud limits and other free hosts (Render, Cloudflare Pages); ECB client behaviour; IMF written permission for scheduled access. (Posit Connect Cloud is now partly covered in the addendum.)

For the user:
