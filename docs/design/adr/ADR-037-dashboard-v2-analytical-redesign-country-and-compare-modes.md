# ADR-037: Dashboard v2 analytical redesign: two modes (Country, Compare), a chart type per analytical question, percentile demoted, empty rows collapsed (amends ADR-030, ADR-026, ADR-034, ADR-036)

Date: 2026-11-12. Companion spec: `docs/specs/dashboard-v2-analytical-spec.md` (chart catalogue, export needs, display rules, AC-V2-*, phasing, change requests).

Labels: [REPO] read in this repository on 2026-11-12; [USER] stated by the user 2026-11-12; [UNVERIFIED] not checked. External URLs: none newly fetched; the IMF terms reading is that of the approved research `docs/research/imf-weo-licence-public-republication.md` (user-approved 2026-11-12), which itself rests on a page summary of https://www.imf.org/en/About/Copyright-and-Terms (accessed 2026-11-07 there; not re-fetched here).

## Context
- User goal [USER]: a working dashboard with different chart types for different analyses, economically correct. Today it shows one chart type (a bar per country plus a "percentile vs all ranked countries" column), and `n/a`, stale and unaligned rows dominate, so the user cannot tell what the dashboard gives for analysis. Two modes are wanted: Country (all data of one country: lines per indicator by domain, small multiples, position against peers, latest-value cards with trend) and Compare (one indicator or direction across countries: multi-country line, ranked bar, scatter of two indicators, heatmap country x period). Percentile becomes secondary. [USER]
- Current state [REPO]: ADR-030 fixed three entity pages (country profile, indicator page, series page) built around the stored percentile and a dot strip; ADR-034 made home the dashboard with cards (ranked bar, heatmap, indicator table, small multiples loaded on demand, KPI tiles); ADR-036 added the hidden-rows disclosure for the Period filter only; ADR-026 makes the percentile the primary rank display and fixes its orientation sentence. ADR-032 (status `proposed`) would add an IMF WEO projection layer on the series page only, Level-only, off by default.
- Data reality [REPO]: the export in `site/src/data` is the synthetic fixture (manifest `code_version: fixture`, 7 indicators M09, M10, M11, P01, A01, B01, M18; the file `meta/series.json` lists synthetic series with one `unit_code`, `frequency`, `seasonal_adjustment`, `price_basis`, `currency_basis`, `base_period` per series). Only two series Parquet files (M09, P01) are present. The measured "real export" figures come from `docs/ops/dashboard-ux-baseline.md` section (e) (the real export directory `data/export/data` is not in the repository now; I did not re-measure): 45 entities (42 countries, 3 aggregates), 80 indicators in 11 domains (72 distinct in domain slots), Eurostat-only run, 3 of 42 countries with a percentile, only `labour` (M09) with any ranked data. The series file holds one row per entity and period for the headline series, latest vintage, observed only, from 1991, with `value`, `value_default_tf`, `value_yoy`, `value_status`, `known_at` (export spec section 6). Series files are therefore the correct and sufficient source for every time-based chart. (Correction by Amendment 1, A1.6: the fixture `meta/series.json` has no `currency_basis`; it has `unit_mult` and `flow_basis`.)
- Incoming data [REPO]: `manual_inbox/imf_weo_manual/2026-10/` holds one WEO CSV (dataset IMF.RES:WEO 9.0.0, edition WEO-2026-10, publication date 2026-10-13; columns include SERIES_CODE, INDICATOR, FREQUENCY=Annual, SCALE, UNIT, LATEST_ACTUAL_ANNUAL_DATA, then one column per year 1980-2031). The series map `config/series_map/imf_weo_files.yaml` maps 151 series: A02 output gap (25 countries), A03 real GDP growth (NGDP_RPCH, % change), A04 general government net lending/borrowing (% of GDP), A05 gross debt (% of GDP), for the 42 panel countries; years after LATEST_ACTUAL_ANNUAL_DATA load as `PROJ`. WEO variables LUR, PCPIPCH, BCA_NGDPD, GGXONLB_NGDP, PPPPC, NGDP_D are explicitly not mapped (decision needed; `imf_weo_files.yaml` header). All WEO series are annual, so WEO adds annual long histories (1991 onward by `valid_from`) that Eurostat's monthly/quarterly series do not have. The WEO CSV is not yet ingested [REPO: no WEO series in the fixture; ingestion status in the real database not checked, UNVERIFIED].
- Hard constraints [REPO]: static site (ADR-010); Observable Framework 1.13.4 + Plot 0.6.18 + d3, no new npm dependency (ADR-023, ADR-024); stored values only, no rank, percentile, mean, quantile, n/N or overall status computed in the browser (ADR-010 decision 1, D6); display-only rebase to 100 is the one approved transform (ADR-030 decision 8); no-JS notice plus static link lists (ADR-025 decision 10); cap of 5 overlaid coloured lines (ADR-025 decision 6); weight limits (ADR-023 decision 6, AC-RD-53); data-only prose rule (ADR-030 content rule).
- Licence caveat [research]: the IMF terms allow republication of database values with IMF attribution; "if material transformation occurs, it must be stated explicitly"; the reading rests on a page summary, not the full page text. This ADR therefore shows WEO values only unchanged (Level) and states any display transform.

## Options considered
1. Structure of the analysis surface.
   a. Keep ADR-034 home (cards for one indicator, ranked bar first) and add chart types as cards. Rejected: it keeps the indicator-first, percentile-first reading the user finds unusable and gives no country-first view of all data.
   b. Two explicit modes, Country and Compare, each a page with its own chart catalogue and shared filter bar (chosen). Maps one-to-one to the user's two tasks; reuses PG-COUNTRY, PG-INDICATOR, PG-SERIES as the stable per-entity URLs that open in the right mode.
   c. A generic chart builder (any x, y, colour). Rejected: steep for the audience and is the "arbitrary query" option ADR-030 option 1c already rejected; it also invites incomparable series on one axis.
2. Position of the peer comparison in Country mode (median band).
   a. Compute quantiles in the browser from the loaded series files. Rejected: D6 forbids computed statistics, and a browser-side median over a user-chosen subset is a new statistic with no stored definition.
   b. Export stored peer statistics (n, min, p25, median, p75, max per indicator, group and period) computed in Python at export time (chosen, change request CR-17). Until it exists, show the country as a highlighted dot among all countries' stored latest values (a strip plot), which needs no statistic.
3. Percentile.
   a. Keep it primary (ADR-026 as is). Rejected by the user's goal.
   b. Remove it. Rejected: the stored percentile is a stored value with a defined orientation and some users want it; removal is irreversible work.
   c. Demote to an opt-in secondary layer: off by default, shown as a column and as dot/bin encoding only when the user turns "Show percentile" on, and only where a stored percentile exists (chosen). Fill of bars becomes neutral by default.
4. Empty, stale and unaligned rows.
   a. Show them grouped after rows with values (ADR-030 decision 5, kept for the tables). Insufficient: the charts the user wants (ranked bar, heatmap, scatter) become mostly empty on the Eurostat-only export.
   b. Hide them in all charts and say nothing. Rejected: an economist must be able to see that a country is missing and why (ADR-030 Q4 reasoning).
   c. Chart marks are drawn only for rows with a plottable stored value; every other row is collapsed into one hidden-rows disclosure per card with the reason category and the list, using the ADR-036 mechanism extended to the reason categories no value, no series, stale, unaligned (chosen).
5. Mixed units and frequencies.
   a. Rescale to a common unit or resample to a common frequency in the browser. Rejected: computation (D6), and for resampling an unstated aggregation rule.
   b. Never put incomparable series on one axis; one unit and one frequency per chart panel; small multiples carry their own axes; incompatible selections are disabled with the stored reason (chosen).
6. Projections.
   a. Add the IMF WEO projection layer to every chart. Rejected: ADR-032 limits it for reasons that still hold (projections have no percentile, no rank, no common reference period).
   b. Allow the ADR-032 layer, once ADR-032 is approved, on the line charts of both modes (country line, multi-country line) as an off-by-default, Level-only layer; never in scatter, heatmap, percentile or default ranking; plus an explicitly labelled projection ranking as a later, separate chart (chosen, conditional on ADR-032 and the licence confirmation).
7. Chart technology.
   a. Add a charting library (ECharts, Vega-Lite). Rejected: no unmet need; Plot 0.6.18 provides line, area, bar, dot, cell, rule, text, tip, pointer, facet and the marks needed [UNVERIFIED for each mark in this repository's installed version; the first implementation task confirms by a smoke render]. 
   b. Plot, d3 and HTML tables only (chosen).

## Decision
1. Two modes. The dashboard has a mode switch, Country and Compare, present on every analysis page. Country mode (PG-COUNTRY, also the target of "Country" in the filter bar) answers "what does the data say about country X". Compare mode (PG-COMPARE, new; PG-INDICATOR becomes its entry with the indicator preselected) answers "how do countries compare on indicator Y or on a direction/domain". State is carried in the URL hash (extends spec 1.5 with `m` = `country|compare`, `x`, `y`, `p`); native controls only. (Amended by Amendment 1, A1.3: `m` and `proj` are removed; `p` is defined.)
2. Chart catalogue, one chart type per analytical question (full specification in the companion spec sections 3 to 5):
   - Country mode: K1 latest-value cards with sparkline; L1 domain small multiples of lines; L2 single-indicator country line with the optional projection layer; P1 position among peers (strip plot now; band with stored peer statistics after CR-17); T1 latest values table (percentile column optional).
   - Compare mode: C1 multi-country line (up to 5 highlighted coloured lines, optional grey context lines); C2 ranked bar of the latest aligned period; C3 scatter of two indicators at a common period; C4 heatmap country x period for one indicator; C5 domain matrix heatmap kept from ADR-034 (secondary); T2 table with sparkline kept.
   - Not offered: pie/donut/funnel (ADR-034 reasons stand), dual-axis charts, composite scores across domains, regression/trend lines, forecasts by own model, any chart that needs an unstored statistic.
3. Percentile demoted (amends ADR-026 decisions 1 to 3 and ADR-030 decision 4). [C5 is percentile-based and is gated on `pc=1` everywhere, decided by the user 2026-11-13, confirmed in chat; see A1.9 item 3.] Default: no percentile on any chart; bar fill is a neutral token; the column "percentile vs all ranked countries" and the dot/bin encodings appear only when "Show percentile" is on (URL `pc=1`, default off) and only for rows with a stored percentile. The orientation sentence (ADR-026 decision 2) is shown exactly when the percentile layer is visible, not otherwise. Everything else of ADR-026 (direction labels, bin tokens, no good/bad colour) is unchanged.
4. Collapse of empty rows (amends ADR-030 decision 5 for charts; ADR-036 extended). Every chart draws only rows with a plottable stored value in the plotted period. All other rows (no value, no series, stale, unaligned, not ranked where ranking is shown) are listed in the card's hidden-rows disclosure, one `<details>` per card, summary = a count sentence with reason categories, body = the list with the stored reason sentence of ADR-030 decision 5. Tables keep the ADR-030 rule (rows without a value after rows with a value, a filter can hide them). The count comes from the same single source as ADR-036 invariant I1 (one function returns the hidden array; the count is its length). This widens the ADR-036 exception from the Period filter to the coverage filter; it is still a count of stored rows by stored state, not a statistic. Stale and unaligned rows are treated as follows: in time-series charts (L1, L2, C1, C4) they are drawn (their history is valid; staleness describes currency, not the past) with the stale marker in the tip; in snapshot charts (C2, C3, P1 strip, K1) they are hidden by default and listed, with a toggle "Include rows from other reference periods" that draws them with their period printed in the label. (Amended by Amendment 1, A1.1 for C4 and A1.4 for the count function, reason categories and sentence.)
5. Economic form (amends nothing; makes ADR-030 decisions 8 and 9 binding per chart; detail in spec section 6):
   - One unit and one frequency per panel; never two indicators on one axis, never a dual axis. Selecting a second indicator in C3 puts it on its own axis (x versus y), not on a shared one.
   - Levels, percentage-point or percent-change series and indexes are labelled as such from the stored indicator and series fields. Index series may be rebased to 100 at a chosen common base period only as a stated display transform ("Index, <period> = 100, rebased for display"); stored `value_yoy` and `value_default_tf` are shown only as columns stored in the series file and named as such. (Amended by Amendment 1, A1.5: no inference from `unit_label` text; rebase gated on stored metadata.)
   - Bars and the color scale of a ranked bar start at zero; lines do not force zero but a zero rule is drawn when the plotted range crosses zero; no log scale.
   - Seasonal adjustment, frequency, unit, reference period and vintage (`known_at`, `known_cutoff`) are printed in each chart's caption block from stored fields; a compare selection whose series differ in unit code, price basis, currency basis or seasonal adjustment is blocked (unit, basis) or marked (seasonal adjustment) as the spec section 6 states.
   - Observed, estimate (EST, PROV) and projection values are visually distinct by non-colour channels (ADR-025 decision 3; ADR-032 decision 6b for projections).
6. Projections (conditional on the user approving ADR-032 and confirming the licence). The ADR-032 layer extends from the series page to L2 and C1 (line charts, Level, annual indicators, off by default). Rejected for C2, C3, C4, K1, P1, percentile. A separate chart "projection ranking" (named C6 here; renamed C7 by Amendment 2, A2.2, because C6 is now the choropleth map) (bars of the stored projected value for a chosen target year, edition named, no percentile) is specified as phase 3 and needs an extra ADR-032 amendment, because ADR-032 decision 1 excludes ranking views. WEO values are shown unchanged; the only permitted display transform on a projected series is none (Level); the rebase is disabled while the layer is on (ADR-032 decision 6a). Attribution string per ADR-032 decision 7b.
7. Country picker. A combobox (text filter plus list, keyboard operable, WAI-ARIA combobox pattern, one native `<input>` with a `<datalist>` is the fallback) over entities of `meta/entities.json`, countries first and aggregates in a labelled sub-list, and a Group select (`meta/groups.json`); selection writes `c` in the hash. The static country link list of ADR-030/ADR-034 stays in the built HTML for no-JS. Details in spec section 5. (Replaced by Amendment 1, A1.2: native `<select>` with `<optgroup>`; no hand-built ARIA combobox.)
8. Export changes (none made here; each needs the user's approval and a separate export-spec amendment). New: CR-16 stored recent-values array (ADR-034 CR-1, re-stated and made phase 2 for sparklines without loading Parquet); CR-17 `peer_stats/<indicator_id>.json`; CR-18 `scale_hint` per indicator (`level|rate|index|change`, drives axis rules without guessing from `unit_label`); CR-19 `meta/indicators.json` `unit_text_varies` and a per-series display unit label (CR-5, CR-6 re-stated); CR-20 per-entity series bundle `series_by_entity/<entity_id>.parquet` if measured Country-mode loading exceeds the 5 MB interaction rule; CR-21 `projection/<indicator_id>.json` is ADR-032 decision 4b, unchanged. Phase 1 needs none of them. (CR-19 field names settled by Amendment 1, A1.6.)
9. Phasing. Phase 1 (Eurostat-only export, no export change): K1 without sparkline (or with sparkline from the loaded series file), L1, L2, C1, C2, C3 (where two indicators share frequency and have at least a few countries), C4, P1 strip, T1, T2, hidden-rows disclosure, percentile toggle. Phase 2 (after WEO ingestion, annual long histories for A02 to A05 for up to 42 countries; or with CR-16 to CR-19): P1 band, scatter and heatmap become populated, cards with stored recent values. Phase 3 (after ADR-032 and the licence confirmation): projection layer, C6 (read C7, Amendment 2, A2.2). The new map C6 is phase 1 (A2.2). The spec states per chart what the Eurostat-only export gives (the chart renders but may show few countries; the spec flags where it would be nearly empty).

## Consequences
- Positive: each of the user's analyses has a named chart with a stated question, export source and axis rule; incomparable series cannot share an axis by construction; sparse coverage is explained by one disclosure per card instead of rows of n/a; percentile stays available without leading; no new dependency; phase 1 ships on today's export with no contract change.
- Negative: more chart modules and tests (about 10 chart types); several charts load many Parquet files (Country mode touches up to 14 indicators per domain); on the Eurostat-only export C2, C3, C4 and P1 will be sparse (3 of 42 countries had any ranked value; the count of countries with a plain value is not measured, UNVERIFIED), so phase-1 value depends on the data, not on this design; the widened hidden-rows exception adds one more browser-side count (of stored rows); WEO-based charts wait for ingestion.
- Risks: the audience and journeys remain unconfirmed (ADR-030 evidence status); scatter of two indicators from different sources can mislead if reference periods differ (mitigated by a common-period rule and a printed period); the diverging colour scale at zero is a display choice that must be stated; IMF licence reading is from a summary; Plot mark availability in 0.6.18 [UNVERIFIED here]; very wide heatmaps for monthly data (mitigated by the window rule).
- Reversal: the modes are new pages and cards on the existing export; reverting restores ADR-034 home and ADR-030 pages; no export file is changed in phase 1.

### A1.3 URL hash keys (amends decision 1 and spec 1.4)
- Remove `m`: the mode comes from the route (`/country/<entity_id>` is Country, `/compare` and `/indicator/<id>` are Compare).
- Remove `proj` until ADR-032 is approved (which would add its own key in its own amendment). Nothing parses or writes `proj` in the meantime.
- `p` is kept with one precise format, the simpler of the two options: a single reference period, used by C3 (and by any snapshot chart that needs one period). Format: annual `YYYY`, quarterly `YYYY-Qn` (n = 1..4), monthly `YYYY-MM`. It is not a range and not an alias of `from`/`to`: ranges of years remain `from` and `to` (existing `site/src/lib/hash.js` keys per the plan, OQ-3 [REPO via plan; the file itself was not re-read]). A value that does not match the format, or is not in the stored common periods, falls back to the default (key omitted).
- Keys added by this design are therefore: `x`, `y`, `p`, `pc`, `ctx`, `oth`, `stl` (A1.1), `rb`. Unknown or invalid values fall back to defaults; all-default state produces an empty hash. Serialization order and parsing are those of the existing hash module with the new keys appended in the order listed [UNVERIFIED against `hash.js`].

### A1.4 Hidden-rows widening: one count function (amends decision 4; proposes amendments to ADR-036)
- Function: `countHiddenRowsByReason(hidden)` in `site/src/lib/filter-model.js`, input the hidden array of a card (each element carries a stored-state `reason`), output `{ total, no_data, stale, other_period, other }`. It is the single count exception to the no-computation rule (ADR-010 D6, ADR-036 decision 6 whitelist): a count of stored rows by stored state, nothing else. It takes over the whitelist slot of `countPeriodHiddenRows` (the whitelist stays exactly one count entry; the Period-filter case is the reason `other_period`). One selection function per chart (`splitByCoverage(rows, context)`, building on `splitByPeriod`) returns `{ drawn, hidden }`; the list renders `hidden`; the counts come from the function above applied to that same array.
- Reason categories, each hidden row in exactly one, assigned by precedence `no_data`, then `stale`, then `other_period`, then `other`:
  - `no_data`: no series for the pair in `meta/series.json`, or a series with no stored value in the plotted period;
  - `stale`: stored `is_stale` true, where staleness hides (C2, C3, P1 strip, C4 without `stl=1`; not K1, which draws stale cards with the stale marker, E-3 decided by the user 2026-11-13 (confirmed in chat));
  - `other_period`: stored alignment is not the chart's reference period, or the row is outside the Period filter;
  - `other`: any other stored state that removes the row (for example not ranked where ranking is shown).
- Summary sentence template (copy.js constant, DRAFT, wording is the user's to confirm): `{N} rows hidden: {X} no data, {Y} stale, {Z} other period` with `, {W} other` appended only when W > 0; any category with a zero count is omitted; singular "1 row hidden: 1 no data". Example: "7 rows hidden: 4 no data, 2 stale, 1 other period". N = `total`; X + Y + Z + W = N. Nothing is rendered when N = 0 (ADR-036 I7).
- List body fields per hidden row: row label (entity name or indicator name as the card's rows are), reason category label, stored reference period of the row's latest value formatted per spec 6.5 (or the stored "not stated" marker), and the stored reason sentence of ADR-030 decision 5. Order: reason category in the precedence order above, then label A-Z.
- Required follow-ups, not edited here: ADR-036 I1 (name of the function), I4 (list shows name and stored period only, no state chip) and the scan whitelist in ADR-036 decision 6 conflict with this item. They need a short ADR-036 amendment (reported in A1.9). RESOLVED [decided by the user 2026-11-13, confirmed in chat]: ADR-036 now carries "Amendment 1 (2026-11-13)" with I1, I4 and decision 6 pointing to it; `countHiddenRowsByReason` takes the single whitelist slot and the widened list body stands.

### A1.5 Rebase before CR-18 (amends decision 5, third bullet, and spec 6.3, 6.4)
- Decision [USER]: no inference from `unit_label` text. Until `scale_hint` (CR-18) exists, L2 shows levels in native units with no rebase. Selections whose units differ use small multiples with independent scales, never dual axes, never a shared axis.
- The rebase control appears only when stored metadata marks the series as an index. The marker is `scale_hint = index` once CR-18 exists. Before that, rebase is OFF [decided by the user 2026-11-13, confirmed in chat; the proposed interim marker `base_period` non-null is rejected and removed].
