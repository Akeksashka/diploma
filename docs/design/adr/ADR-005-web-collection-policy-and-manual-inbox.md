# ADR-005: Web (HTML/PDF) collection as last resort under a fail-closed gate, and a manual-inbox route for files a human must download

Revision note (review fixes): WEO reminders now fire after the expected release (25 April and 25 October) instead of 25 March and 25 September (A10). Round 5 (2026-10-24): reminders are configured on the preflight day (25th) with the expected window ending on the 24th; manual editions carry an edition date and an older edition is refused unless labelled as an archive import (P22, confirmed by the user on 2026-10-24, design Q47).

## Context
- The user wants GitHub Actions to also collect information from websites. CLAUDE.md: respect source terms, rate limits and robots.txt; scraping is the last resort (architect brief).
- National sources for China, Saudi Arabia, South Africa and India have no confirmed programmatic route (GASTAT publishes pages/PDF; NBS China no documented API; India MoSPI portal API is new and unverified; South Africa only a community mirror). Terms and robots.txt for all national sites were not checked (data-sources research F7, risk 7, open question 9).
- OECD and ILOSTAT pages return HTTP 403 with a Cloudflare-style "Just a moment" bot challenge to the researcher's environment; OECD documentation (search result) says VPN or anonymised traffic is not allowed (data-sources research F3). GitHub-hosted runners come from data-centre address ranges; whether these sources block them is [UNVERIFIED].
- D23 / U2: the project will not bulk-download IMF data by automation; IMF WEO files are downloaded manually in April and October. The IMF terms prohibit "bulk download of information by automated technology without explicit permission" (https://www.imf.org/en/About/copyright-and-terms, as quoted in data-sources research F2).
- Playwright is available (Apache-2.0) but heavy (tooling research, B).

## Options considered
1. Scrape freely wherever data exists; add a headless browser when needed.
2. A fail-closed web connector (HTML via httpx + lxml; PDF via pdfplumber only if no HTML/CSV equivalent), enabled per site only after a recorded terms and robots review; no circumvention of access controls; a `manual` connector as fallback.
3. No web collection at all; leave gaps as n/a (D3, D16).

## Decision
Option 2.
- A `web` source entry is rejected at config validation unless `terms_review` has `decision: permitted`, a `reviewed_on` date no older than 12 months, a URL, and a quoted clause; `enabled: true` additionally requires the same for `robots_review`. A source whose review is missing is loaded as `enabled: false`.
- At run time the `RobotsGate` fetches `/robots.txt` for each host (cached 24 h in `ingest.request_state`), evaluates the exact URL for the project User-Agent, honours `Crawl-delay` and fails closed: disallowed or unreadable robots (other than 404, which means no restrictions) skips the source and raises an alert. The decision and the robots hash are stored on each `ingest.raw_object` (`robots_checked_at`, `robots_decision`).
- Politeness defaults for `web`: 1 request per 5 s per host, 1 concurrent request, no more than 100 requests per source per run, conditional requests, daily at most (monthly in practice), identifying User-Agent (repo URL, "non-commercial"), no login-gated pages, no cookies except those the server sets for session continuity.
- No circumvention: no challenge solvers, rotating proxies, VPNs, header spoofing, or headless browsers by default. A bot challenge (HTTP 403/503 with challenge markers) is classified `blocked`, recorded, alerted once per source per month, and the source falls back to the manual-inbox route. Playwright requires a new ADR and a per-site terms review.
- Layout-drift protection: every HTML/PDF parser declares expected structure (table header texts, minimum row count, period format); mismatch is a `parse` error that blocks that source group's load and never loads partial data silently.
- `documented API` and `published bulk file` sources (Eurostat, BIS, WB, ECB, FAO, EC, etc.) are not "web" sources, but the same `RobotsGate` runs in log-only mode; a robots Disallow on a documented endpoint is escalated to the user rather than overridden (`robots_override_reason` can be set by the user, never by the agent).
- Manual inbox (`manual` connector): a human downloads a file from the publisher's site and commits it to `manual_inbox/<source_id>/<YYYY-MM>/<file>` together with `<file>.meta.yaml` (`source_url`, `downloaded_on`, `downloaded_by`, `edition_label` such as `WEO-2026-10`, `edition_date` = the publication date of the edition, `licence_note`, and optionally `import_label: archive_import`). A push under that path triggers `ingest-manual`, which hashes, archives (ADR-003, `manual = true`) and parses the file. This is the only route for IMF WEO (D23). The file format and parser are fixed only when the first real file is available (open question Q2).
- Manual edition order (round 5, P22, confirmed by the user on 2026-10-24, design Q47). Ordering the loader by `fetched_at` alone lets an older WEO edition that a human commits later become the "latest" one. Rule for groups declared `edition_ordered: true` (WEO): the loader orders manual files by `edition_date` and compares the `edition_date` of the object with the greatest `edition_date` among the already LOADED objects of the same `(source_id, group_id)`. An object with a smaller `edition_date` is not loaded: it is recorded `skipped_out_of_order` (`detail.reason = 'older_edition'`, a terminal outcome that does not block later objects) and check ORD-03 (warn) opens an issue; an equal `edition_date` (a corrected file of the same edition) is allowed. A human who really wants the older edition in the database re-submits it under a new path with `import_label: archive_import` in the sidecar; such an object is loaded with `load_kind = 'import'` (ADR-002): its rows are stored and labelled, never become "latest", and are excluded from every real-time claim and from analytics (ranks, alerts), the export and the revision views. In the forecast store proposed by ADR-011 such imports become editions with `imported = true`. "Latest WEO edition" for the A02 estimate boundary is read from `raw_object.edition_label`/`edition_date` of the latest loaded edition, never from the `vintage_label` of rows, because rows that are unchanged across editions are not re-inserted and keep the older label.
- Which national websites are onboarded is a user decision after terms review; the design does not assume any.

## Consequences
- Coverage of China, Saudi Arabia, South Africa, India monthly series may stay thin (consistent with D3, D16); manual inbox is the pressure valve.
- A committed manual file stays in git history (WEO files are a few MB, twice a year; acceptable; `.gitattributes` not required below 100 MiB).
- Human steps (April and October WEO) need a reminder that fires AFTER the expected release (A10): the `preflight` workflow (which runs only on the 25th of every month) opens a GitHub Issue "WEO manual download due" on 25 April and 25 October if no inbox file for the edition exists, with text saying that the edition is expected to be out (mid-April and mid-October) and asks for the download. Round 5: the configured `remind_on` day is 25 (a day later than the 25th could never fire, because preflight does not run on the 26th) and the configured expected window ends on the 24th, so the reminder day is after the window; the reminder is evaluated at the first preflight on or after `remind_on` (source-config rule 11). The release months are [UNVERIFIED, to confirm against https://www.imf.org/en/Publications/WEO]; the earlier 25 March / 25 September dates would have fired before the edition exists. FRESH-03 escalates 45 days after the first of the release month. If scheduled workflows were disabled the reminder would not fire; the human monthly check covers it (workflows spec section 9).
- Fail-closed gating makes onboarding a web source deliberately slower than an API source.
- An older edition committed by mistake is not loaded silently; the cost is one extra human step for deliberate archive imports.
