# ADR-029: When a source supplies no unit for a series, the series-map `expect.unit` supplies it (explicit per-group opt-in, applied in the loader; amends ADR-018 decision 2 and the META-02 reading of `expect`)

Date: 2026-11-06 (Phase 2). Repository facts were read from files on 2026-11-06 (code read, nothing executed, no database, no network, no `.env`). The behaviour of the World Bank API comes from the project's own run of 2026-11-05 (as reported by the user) and the DE probe of 2026-11-06 recorded in `docs/ops/spike-results.md` (OP-04 section, "NY.GDP.MKTP.CN / NY.GDP.MKTP.CD (DEU) ... row `unit` empty"). No World Bank documentation was consulted for this ADR: the claim that the API leaves `unit` empty for all indicators (not only the ones observed) is [UNVERIFIED] beyond the five indicators of `worldbank_annual` and the two of `worldbank_support`. Access date for those internal records: 2026-11-06. User direction recorded: option "a", 2026-11-06 (stated in session).

## Context
- Observed (run 2026-11-05, group `worldbank_annual`): every World Bank API v2 data row carries `"unit": ""`. `src/macro_monitor/ingestion/parsers/worldbank_v1.py` line 86 emits `unit_code=str(row.get("unit") or "")`, i.e. `''`. The parser is `FROZEN once released` (its docstring) and listed in `RELEASED_PARSERS` as `worldbank_v1@1` (`src/macro_monitor/ingestion/registry.py`).
- `config/series_map/worldbank_annual.yaml` (210 entries: 5 indicators x 42 countries) declares `expect: {frequency: A, unit: <USD|YEARS|INDEX|PCT>, seasonal_adjustment: NA, price_basis: NA}` per entry. By indicator: `NY.GDP.PCAP.PP.CD` USD, `SP.DYN.LE00.IN` YEARS, `SI.POV.GINI` INDEX, `SL.TLF.CACT.ZS` PCT, `FI.RES.TOTL.CD` USD (read from the file, key blocks at lines 5, 509, 971, 1475, 1979).
- The loader (`src/macro_monitor/storage/loader.py`, per-series loop lines 230-267) does two things with the staged metadata: for an unknown series it calls `first_sight_problems` (`src/macro_monitor/storage/series_create.py` lines 267-304), which runs `expect_problems` (staged `unit_code` compared with `expect.unit`, line 224-234) and requires the unit to exist in `ref.unit`; for a known series it calls `diff_meta` (lines 212-221), which compares staged and stored attributes and treats `''` as a published value (only `None` is skipped, line 217). `''` differs from `'USD'`, so a drift event of kind `unit` is opened in `ops.drift_event` and the series is deferred in `ingest.raw_series_status`. Result of the run: 145 series deferred, nothing loaded. (210 mapped entries vs 145 deferred is not reconciled in this ADR; see Open questions.)
- Rules that apply: every series carries source, series id, frequency, unit, seasonal adjustment, vintage (`CLAUDE.md`); `ref.series.unit_code` is `NOT NULL REFERENCES ref.unit` (`src/macro_monitor/storage/migrations/0001_ref.sql` line 150), so a blank unit cannot be stored and a unit must exist in `ref.unit`; ADR-018 decision 2 requires that the published metadata equals the entry's `expect` block (META-02) before a row is created; `ref.series` measurement attributes are immutable (ADR-002), so a wrongly fixed unit is only corrected by a new series version.
- A precedent exists and shows the cost of the alternative: `worldbank_v2` (`src/macro_monitor/ingestion/parsers/worldbank_v2.py`) fills `unit`, `currency_code` and `flow_basis` from a hard-coded two-indicator table in the parser (`NY.GDP.MKTP.CN`, `NY.GDP.MKTP.CD`), used only by the parked group `worldbank_support` (`config/sources.yaml`, `parser: ...worldbank_v2:parse`, `enabled: false`). `docs/ops/spike-results.md` (OP-04) states that "parser fills LCU / USD", which holds for `worldbank_support` but not for `worldbank_annual`, which still uses `worldbank_v1`.
- Replay rule: `parse` is a pure function of the bytes, the parser version and `series_filter` (`docs/specs/ingestion-interfaces-spec.md`, section 2, line 82); old raw objects are re-staged with the recorded `parser_id` (loader step 4, line 160) and `registry.py` says that a released entry is never edited. The loader already depends on configuration at the run's `git_sha` (series map via `git_map_provider`, ADR-018) and replay uses configuration as recorded (spec line 255, `ref.config_history`, ADR-002).
- Side findings that this ADR does not decide but that block the 145 series from loading (verified in the migrations, `src/macro_monitor/storage/migrations/0001_ref.sql` lines 210-219, 0010, 0013, 0014, 0015): `ref.unit` has no `YEARS` and no `INDEX` (the seeded index unit is `IDX`, "base period in ref.series.base_period"); the first-sight precondition "unit exists in `ref.unit`" would therefore still fail for 84 of the 210 entries (life expectancy `YEARS`, Gini `INDEX`) after this ADR. `A01` is declared `USD` while `INTL_USD_PPP` is seeded and the indicator is "GDP per capita, PPP (current international $)" (rationale text in the map): a semantic question for the user, not a technical one.

## Options considered
1. Drop `unit` from `expect` for World Bank (or for all) and take the unit from nowhere: the series would have no unit, which breaks the "every series carries a unit" rule and `ref.series.unit_code NOT NULL`. Rejected.
2. Accept a blank unit (`''`) as the published value and skip the META-02 unit check: `''` is not in `ref.unit`, the FK rejects it, and a blank unit would defeat the later detection of a unit change (a source that starts to publish `USD` would "drift" from `''`). Rejected.
3. Hard-code units in the parser (extend the `worldbank_v2` table to the five indicators, or add `worldbank_v3`): keeps the loader unchanged but moves a per-series fact into code (a second place to maintain besides the series map, which already declares it and is reviewed), needs a new frozen parser version for each indicator batch and a new `RELEASED_PARSERS` entry, and makes the parser disagree with the reviewed `expect` the moment someone edits one of the two. Rejected as the general mechanism; `worldbank_v2` is left as it is.
4. The series-map `expect.unit` supplies the unit when the staged unit is empty, applied for every group automatically (user direction "a", unqualified). Works with no config change, but silently turns a source regression into a loaded series: if Eurostat/BIS/ECB (`jsonstat_v1.py` line 225, `bis_v1.py` line 137, `ecb_csv_v1.py` line 95 all default to `''`) lose the unit dimension, the loader would fill it from config instead of raising drift. These sources publish a unit, so an empty unit there is a defect to see.
5. Same as 4 but only for groups that declare it (opt-in key on the group). Recommended.
6. Apply in the staging step (write the config value into `staging.series_meta_load`). Rejected: staging must hold what the parser emitted from the bytes (replay and re-stage from raw produce the same staging rows with or without config); the config would leak into a layer that today has none, and the re-stage path of step 4 would have to do the same.

## Decision
Option 5 (a refinement of user direction "a", 2026-11-06). Needs the user's approval of item 2 in particular.

1. Precedence, one pure function `effective_unit(staged_unit, entry.expect.unit, group_opt_in)` used everywhere the loader reads the staged unit. "Empty" means `None`, `''` or whitespace only; a non-empty value is never trimmed, case-folded or mapped.
   | staged unit | `expect.unit` | group opt-in | effective unit | result |
   |---|---|---|---|---|
   | non-empty `U` | absent | any | `U` | as today |
   | non-empty `U` | `E`, `U = E` | any | `U` | as today, no event |
   | non-empty `U` | `E`, `U != E` | any | `U` | META-02 mismatch: drift event kind `unit` (old `E`, new `U`), series deferred; the API value always wins and is never overridden by config |
   | empty | `E` non-empty | yes | `E` | no event; counted as `unit_from_expect` |
   | empty | `E` non-empty | no | empty | drift event kind `unit` (old `E`, new `''`), series deferred, as today |
   | empty | absent | any | empty | rejected: drift event kind `unit` (old `non-empty unit`, new `''`), series deferred; no row with a blank unit is ever written |
   The effective unit must also exist in `ref.unit` (unchanged ADR-018 precondition); a missing unit code is a `unit` event with old `in ref.unit`.
2. Scope: explicit opt-in, not global. A new optional boolean group key `unit_from_expect` (default `false`) in `config/sources.yaml`. Only `worldbank_annual` sets it to `true` in this change. Why minimal: the rule is a fallback for a source that is known to publish no unit; the series map is reviewed and per series, so it is the right source of the value, but the decision "this source publishes no unit" is a fact about the source and belongs on the group, where a reviewer sees it once. For other groups an empty unit stays a visible defect (Option 4). Config validation rule (new, additive): a group with `unit_from_expect: true` requires every entry of its series map to carry `expect.unit`; `sync-config` fails otherwise. If the user prefers the unqualified rule (Option 4), drop the key and this validation rule; nothing else in this ADR changes.
3. Where: loader / validation layer, not the parser and not staging. `effective_unit` is applied (a) in `expect_problems` and `first_sight_problems` (first sight), (b) before `diff_meta` for an existing series (so a known series with stored `USD` and staged `''` is not drift, and an `expect.unit` changed to another value still is: effective `EUR` vs stored `USD`), and (c) in the release path `release_deferred` / `_release_one` (`loader.py` lines 997-1011, which call `first_sight_problems` and `create_series` with the staged meta), and the value written to `ref.series.unit_code` by `create_series` is the effective unit. For the known-series branch the loader needs the group's map entry and flag (today `entries` is read only when `stored is None`, lines 236-238); it reads them from the config at the run's `git_sha` by the same route as ADR-018. `unit_mult` is not part of this rule (it stays as parsed, 0).
   - Provenance: the load counts `raw_load.detail.unit_from_expect` (number of series for which the config value was used); no new column and no change to `ref.series` (the stored unit is the same kind of fact either way).
   - Parser versioning: no parser changes. `worldbank_v1@1` stays frozen and keeps emitting `''`; `RELEASED_PARSERS` is unchanged; no `worldbank_v3`. `worldbank_v2` (parser-filled unit for two indicators, parked group) stays as released; under the rule its non-empty unit is "staged non-empty" and is compared with `expect.unit` like any API value.
   - Replay and rebuild determinism: parsing and staging are byte-for-byte unchanged, so old raw objects re-parse identically (spec line 82; AC-ING-11). The only new input to the loader result is `expect.unit` and the group flag, both read from the configuration at the run's recorded `git_sha`, the same input class that ADR-018 first-sight and META-02 already use; rebuild with the recorded configuration gives identical `ref.series` rows. Rebuild with a different `git_sha` is outside the guarantee, as it already is for every `expect` field.
4. Migration and config-schema impact. Database: none for the rule itself (no DDL, no change to `ops.drift_event` kinds, no privilege change). Config schema: one additive optional key `unit_from_expect` on a group (`src/macro_monitor/registry/schemas/sources.schema.json`, `docs/specs/source-config-schema.md`) with the validation rule above; `config/series_map/*.yaml` format unchanged. This differs from the "none expected" of the direction in the task, and is the price of Decision 2; with Option 4 the schema impact is zero. Separately, and not part of this rule, loading `worldbank_annual` needs `ref.unit` rows for `YEARS` and `INDEX` (forward-only seed migration in the style of 0010, 0013, 0014, 0015) or a change of the codes in the map to seeded ones (for example `IDX`); see Open questions.
5. The 145 open drift events (not decided here; user decision). They are kind `unit`, old `E`, new `''`, with `ingest.raw_series_status` rows `deferred` and the object's staging rows (swept after 14 days, spec step 4; re-staged from stored raw if needed).
   - R1 (recommended): after this ADR is approved and implemented, record decision `accepted` on each event with a note that cites ADR-029; the next `load --drain` releases the deferrals from the stored raw bytes without refetching (`release_deferred` re-stages the object, creates the series with version 1 through the shared first-sight function and loads with the original `known_at`). Pro: no refetch, original `fetched_at` preserved, uses the existing path. Con: "accepted" is worded for a source change, here it records "the event was caused by the pipeline, not the source"; the note must say so. Events for `YEARS` and `INDEX` stay pending (`config_not_updated`) until the `ref.unit` question is settled.
   - R2: record `rejected` on all 145 and fetch again. Pro: wording is neutral. Con: a rejected deferral is final for that object (`rejected` is appended, nothing loads); an unchanged source (`lastupdated` and content hash equal) may skip the refetch by change detection, so a forced refetch is needed [UNVERIFIED how to force it]; a second raw object is stored for the same data.
   - R3: leave them open. Con: nothing closes them, they remain in the open-events views and the monitoring noise; the deferrals never load.
   - R4 (not recommended): hand-edit the database. Forbidden by `CLAUDE.md` (no UPDATE/DELETE outside the pipeline).

## Consequences
- Pro: the series gets its unit from the reviewed map, the API's own unit always wins and a real mismatch is still a drift event; blank units are impossible; no parser release and no migration for the rule; Eurostat/BIS/ECB keep failing loud on a missing unit; replay stays deterministic.
- Con: the unit of a World Bank series is now a configuration fact not confirmed by the source, so a wrong `expect.unit` fixes a wrong immutable series attribute (corrected only by a new version, ADR-002), and a source that starts publishing a unit that differs from `expect.unit` surfaces as drift only from then on; the loader reads the map and flag also for known series (a small cost per object); one more group key and validation rule to maintain; the parser docstring `worldbank_v1.py` ("optionally `unit`") and `spike-results.md` ("parser fills") remain accurate for what they describe, but readers must follow this ADR for `worldbank_annual`.
- Does not by itself make the 145 series loadable: `YEARS`, `INDEX` are not in `ref.unit` and the `A01` unit code is questionable (see Open questions). Without that decision 84 of 210 entries stay deferred under a different `unit` event.
- Reversal: remove the group key; the loader returns to the strict comparison; series already created keep their unit (it is a stored attribute, not recomputed).
- Tests (acceptance criteria, all unit tests without network or database unless marked `db`):
  - AC-UNIT-1: a table-driven test of `effective_unit` over the six rows of Decision 1 plus whitespace-only and `None` as empty and a non-empty value with different case (`usd` vs `USD`, which is a mismatch, not equal).
  - AC-UNIT-2 (`db`): staged unit `U`, `expect.unit` `E != U`, opt-in true: no `ref.series` row, one `unit` drift event (old `E`, new `U`), the series deferred; with `U = E`: created.
  - AC-UNIT-3 (`db`): staged `''`, `expect.unit` `USD`, opt-in true: `ref.series.unit_code = 'USD'`, observations loaded, no drift event, `raw_load.detail.unit_from_expect` equals the number of such series.
  - AC-UNIT-4 (`db`): staged `''`, no `expect.unit`: no row, one `unit` event with new `''`, deferred; no `ref.series` row ever has `unit_code = ''` (FK).
  - AC-UNIT-5 (`db`): staged `''`, `expect.unit` present, opt-in false (and the same for a `jsonstat_v1` fixture without a unit): drift event as today (regression guard that the rule does not leak to other groups).
  - AC-UNIT-6 (`db`): known series stored `USD`: staged `''` plus `expect.unit USD` loads without an event; same with `expect.unit EUR` raises a `unit` event (old `USD`, new `EUR`) and defers.
  - AC-UNIT-7 (`db`): effective unit not in `ref.unit` (`YEARS` before its seed) raises a `unit` event with old `in ref.unit`, nothing created.
  - AC-UNIT-8: parsers are untouched: `RELEASED_PARSERS` keys equal the set before this change; the golden parse of the World Bank fixture through `worldbank_v1@1` still has `unit_code == ''`; `tests/unit/test_ingestion_parsers.py` passes unmodified.
  - AC-UNIT-9 (`db`): determinism: loading a recorded `worldbank_annual` raw object directly, and loading it by `rebuild` (empty database, same `git_sha`), yield identical `ref.series` and `curated.observation` rows; the staged `series_meta_load.unit_code` is `''` in both.
  - AC-UNIT-10 (`db`): release path: a deferral from AC-UNIT-4's setup, after the config gains `expect.unit` and the event is `accepted`, is released from the stored raw bytes with the original `known_at` and the effective unit.
  - AC-UNIT-11: config: the JSON schema accepts `unit_from_expect: true|false`, rejects a non-boolean; `sync-config` fails for a group with the flag whose series map has an entry without `expect.unit`; the real `config/sources.yaml` and `config/series_map/worldbank_annual.yaml` pass (all 210 entries carry `expect.unit`).
- Amends (without editing them):
  - ADR-018 decision 2 ("the published metadata must equal the map entry's `expect` block (META-02)"): for `unit` the comparison is made on the effective unit of Decision 1 of this ADR; the Pro "the row always reflects what the source published" holds for the unit only when the source published one or the group opted in.
  - `docs/specs/validation-monitoring-spec.md` META-02 ("published metadata equals `expect`"): same qualification for the `unit` attribute; its drift kind and severity are unchanged.
  - `docs/specs/ingestion-interfaces-spec.md` section 6 step 6 (compare with stored attributes; first-sight preconditions) and the deferred-series paragraph after step 10: the staged unit is replaced by the effective unit before comparison and creation; the release path uses the same function.
  - `docs/specs/source-config-schema.md`: the new group key `unit_from_expect` and its validation rule; the sentence on `expect` in the series-map section (line 370, "drift check against published metadata") gains "or supplies the unit for a group with `unit_from_expect`".
  - Not amended: ADR-009 (mapping), ADR-002 (immutability and the succession rule apply as before), ADR-007 (drift events and human decisions unchanged). The comment in `config/sources.yaml` for `worldbank_support` (parser-assigned unit) stays true and is not touched.

## Open questions for the user
1. Scope: opt-in per group (this ADR, adds one config key) or the unqualified rule for all groups (user direction "a" as stated; zero config change, masks a missing unit in Eurostat, BIS, ECB)?
2. `YEARS` and `INDEX` are not in `ref.unit`. Add them by a forward-only seed migration, or change the map codes (for example `IDX` for the Gini index; no seeded code exists for years)? The migration may be applied to `neondb` only on your explicit request. Needed for 84 of the 210 entries.
3. `A01` (`NY.GDP.PCAP.PP.CD`, "current international $") is declared `USD`; `INTL_USD_PPP` is seeded. Correct the map before first sight, because the unit is immutable once created?
4. The 145 events: R1 (accept with an ADR-029 note and drain), R2, or R3? Recommended R1, after the questions above are settled. Why 145 and not 210 (65 series not deferred for this reason, or absent in the fetched object) is not explained by the files read; check before deciding.
5. `worldbank_support`: leave the parser-filled units (`worldbank_v2`) as they are, or later move its units to `expect.unit` plus the flag (and retire the parser table in a future parser version)? Not needed now.
