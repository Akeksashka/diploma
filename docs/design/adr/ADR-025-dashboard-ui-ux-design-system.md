# ADR-025: Dashboard UI/UX design system (tokens, colour scales, state vocabulary, typography, accessibility, print) for V1-V5

Amended by ADR-034 and docs/specs/dashboard-layout-amendment.md (2026-11-10).

Date: 2026-11-04. Extends ADR-010 (decisions 1, 8, 9, 10), ADR-023 (decision 4: no off-origin request, `globalStylesheets: []`; decision 6: bundle-size rule) and ADR-024 (no dependency beyond its list). Changes none of them. User requirement stated in session on 2026-11-04: "I want the final visualisation to be beautiful and informative for UI/UX", to be done after the Eurostat throwaway run. Detail lives in `docs/design/briefs/dashboard-ux-brief.md`. Labels: [DOC] read on the primary page this session; [SEARCH] search-summary only; [REPO] read in this repository; [CALC] hand calculation; [UNVERIFIED] not checked. Access date for every URL: 2026-11-04.

## Context
- Today's site [REPO]: five view families (V1-V5) render correctly from the fixture export but are styled by per-renderer inline `<style>` strings with hard-coded light colours, no dark theme, no print rules, no web font, `steelblue` dots, and a V1 detail table in long form. There is no country-by-indicator matrix, no colour encoding of the percentile, and no shared vocabulary for stale, unranked, n/a, lagging, descriptive or not-published states beyond text flags.
- Constraints already approved: the browser only displays stored ranks and percentiles and never recomputes them (export spec principle 3, ADR-010 decision 1, user decision D6); fixed and user-confirmed wording (V1-V5 sections of `docs/ops/spike-results.md`, export spec sections 5, 7); no request leaves the origin and fonts are self-hosted only (ADR-023 decision 4); landing view at most 1.5 MB gzipped, one explorer interaction at most 5 MB gzipped (ADR-023 decision 6, user decision in the T92 section); only the dependencies in ADR-024 (Framework 1.13.4, Plot 0.6.18, d3, Arrow, parquet-wasm, Playwright).
- No real export exists yet: the Eurostat throwaway run stopped at the `fetch` step (`c[TIME_PERIOD]=ge:1991` rejected by the live API, last section of `spike-results.md` [REPO]). Densities and sizes below come from the spec and the fixture and are re-checked on the first real export.
- Facts used: WCAG 2.2 AA includes 1.4.11 Non-text Contrast (3:1) [DOC: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html], new AA criteria 2.4.11 Focus Not Obscured (Minimum), 2.5.7 Dragging Movements, 2.5.8 Target Size (Minimum, 24 x 24 CSS px), and 4.1.1 removed [DOC: https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/]; Reflow at 320 CSS px with an exception for data tables in their own scroll container [DOC: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html]; Inter is under the SIL OFL 1.1 [DOC: https://github.com/rsms/inter/blob/master/LICENSE.txt]; Framework themes follow `prefers-color-scheme` when a light and a dark theme are both active [SEARCH: https://observablehq.com/framework/themes, https://observablehq.com/framework/css/color; the official pages returned HTTP 429 to a direct fetch this session].

## Options considered
1. Keep the current per-renderer styling and only polish. Cheapest; leaves dark theme, print, state vocabulary and accessibility unspecified and untestable. Rejected.
2. Adopt a component/CSS library (Tailwind, a design-system package, a chart-theme package, an icon font). Faster visuals, but each is a new dependency or an off-origin asset (ADR-024 rule 1, ADR-023 decision 4), with supply-chain cost out of proportion to a five-view static site. Rejected.
3. A small hand-written design system: one global stylesheet with CSS custom-property tokens, HTML/CSS heatmap and state chips, Plot for time series and dot plots only, one optional self-hosted font, tests that measure contrast, states, focus, size and fixed wording (chosen).
4. Colour scale for percentile: (a) diverging red-green or red-blue around 0.5; (b) sequential single hue in 5 fixed bins (chosen); (c) continuous ramp without bins. (a) reads as good/bad although the standing caveat says the percentile is not a judgement, and works badly for colour-vision deficiency and greyscale print. (c) has no legend that maps to a text label and no safe text colour per cell. Diverging is kept only where the sign is the data (revisions, deviation from target).
5. Typography: (a) system font stack only (0 bytes, no licence, platform-dependent look); (b) one self-hosted variable family, Latin subset (about 90 KB [SEARCH], consistent look, tabular figures); (c) several families. (b) recommended, (a) is the fallback and a valid whole answer (open question Q1); (c) rejected.
6. Heatmap implementation: (a) Plot `cell` mark in SVG; (b) HTML `<table>` with CSS fills (chosen). (b) gives native table semantics, keyboard and screen-reader reading, text in every cell, sticky headers, print and forced-colors behaviour, and costs no JavaScript library.

## Decision
1. Design system. One global stylesheet `site/src/style.css` with CSS custom-property tokens (`--mm-*`) for surface, text, percentile bins, diverging sign, alert, feed state, focus, spacing and type; light by default and a dark override in `@media (prefers-color-scheme: dark)`; no manual theme toggle in v1 (Q2). The per-renderer inline `<style>` strings are removed in Stage 0. Hex values in the brief are candidates; contrast is proven by AC-UX-1 before use. Framework's own theme supplies the base page colours; our tokens define data encodings and components only (coupling to Framework variable names is checked in Stage 0 [UNVERIFIED]).
2. Percentile encoding. Sequential single hue, 5 fixed bins on the stored percentile (edges 0.2, 0.4, 0.6, 0.8), a fixed ink token per bin, numbers always printed in the cell, in the existing stored formatting (no x100 without Q4). No good/bad colouring of a percentile. Diverging blue-orange scale only for revisions and deviation from target, with the sign always printed as text and a triangle.
3. State vocabulary. Every state in `scorecard.js` (ranked, stale, lagging, unaligned, ahead, descriptive, n/a, not published, aggregate, inherited, estimate, low coverage, alert level watch/alert) and the feed states (fresh, late, stale, broken) gets a visible text code, a non-colour signature (hatch, dotted border, crossed box, hollow ring, triangle, diamond, check, clock, hourglass, cross) and an accessible name, as tabulated in the brief section 5. Colour is a third channel only.
4. Heatmaps. V1 domain page: HTML table, countries x the domain's indicators, a separated leading column "mean percentile of the domain's indicators" (stored `percentile_rank`), n/N and position as today; aggregates in a separate group; detail table kept inside `<details>`. V1 landing: countries x ranked domains using the stored domain figure, with NO overall column, no row aggregate, no composite sort (U1: no composite rank); default order alphabetical, column sort by stored `rank_position`. Landing heatmap is conditional on the weight check of AC-UX-12 (needs all domain scorecards, outside the "one domain" landing-set definition of export spec section 8); otherwise the landing stays a domain list with per-domain heatmaps (Q5).
5. Typography. Recommended: Inter variable, Latin subset WOFF2, SIL OFL 1.1, committed under `site/src/fonts/` with `OFL.txt` and a source/checksum note, no npm package (a `@fontsource/*` package would be a new dependency needing its own ADR); `font-display: swap`, one preload, size-adjusted fallback; `tabular-nums` for all numbers. Size cost about 90 KB for a Latin-only variable file against the 1.5 MB landing limit [SEARCH, third-party estimate, not measured]; measured in Stage 0 with the other landing files. Fallback and zero-cost alternative: a system font stack. Decision between the two is the user's (Q1); the token and layout work does not depend on it.
6. Charts. Direct labels for up to 5 series, small multiples above 5; categorical hues limited to 5-6 and paired with dash or marker shapes; hollow markers for estimate/provisional values; revised-data-history rings; a visible vintage (`known_at`) of the last point; no confidence bands (none are exported); no interpolation; rebase marked by an index-100 rule and a base-period rule; every chart in a `<figure role="img">` with a generated text alternative built from stored fields and a "View as table" disclosure (latest 24 periods per series plus a download link), so tooltips are never the only access. No drag-only interaction (2.5.7).
7. Layout and responsiveness. Three width classes; compact collapses explorer controls, turns the V2 table into cards, and scrolls heatmaps horizontally inside their own container with a sticky country column (data-table reflow exception [DOC]); no page-level horizontal scroll at 320 CSS px.
8. Accessibility target: WCAG 2.2 AA. Text 4.5:1, non-text 3:1, visible focus ring with offset that is never covered by sticky headers, targets at least 24 x 24 CSS px, real table semantics (caption, `th scope`, sortable headers as buttons with `aria-sort`), landmarks, skip links, reduced-motion, forced-colors and dark-mode support. Screen-reader quality is proven partly by automated DOM checks and partly by a recorded manual check (the user or a named reviewer with VoiceOver; Q7).
9. Print. A print stylesheet forces the light tokens, hides controls, expands `<details>`, keeps fills and patterns, repeats the freshness line, caveat, sources and URL.
10. States. Loading (reserved height, `aria-busy`, text, no shimmer), no-JS notice, empty (confirmed strings plus a next step), error (`role="alert"`, logical name of what failed, consequence, no URL or raw error text, never partial numbers). Stale banner unchanged in wording, moved to the shell on every page.
11. Microcopy. A single module `site/src/lib/copy.js` holds fixed and confirmed strings; a test asserts the fixed strings verbatim and the absence of "first release", "first stored release" and judgement words next to percentiles. The redesign changes layout, not any confirmed string. New strings (bin labels, state codes, loading/error sentences, print footer) are listed in the brief section 11 and need the user's confirmation before they ship.
12. Staging (details in the brief section 14): Stage 0 foundation (tokens, shell, copy module, fonts, test harness); Stage 1 state vocabulary and V1 domain heatmap; Stage 2 landing heatmap (conditional); Stage 3 V2; Stage 4 V3; Stage 5 V4 and V5; Stage 6 print, polish, cross-browser and screen-reader checks. Stage 0 is gated on a real export (or the user accepting the fixture density) because heatmap width, label length and landing weight depend on real data.
13. No new dependency. Colour tables are written by hand; contrast is computed by a small repository script (no library); no axe-core, no `@playwright/test`, no icon or colour package. If the user wants any of them (Q8) a separate ADR under ADR-024 rule 1 is needed first.

### How the decisions respect the fixed rules
- D6: each visual channel is a function of one stored field (bin from stored percentile, sort from stored `rank_position`, glyph from stored flags); no mean, rank, composite, overall status or position is computed; the only display scale is a revision bar length relative to the largest value shown, labelled as such. AC-UX-10 checks it.
- No off-origin request: the font and all icons are same-origin; no CSS `@import url(http...)`, CDN, analytics or tile service. AC-UX-11 extends AC-DASH-1 / AC-NPM-3.
- Budgets: no new JavaScript; CSS target at most 20 KB gz; font about 90 KB (to be measured); internal target for the landing set at most 600 KB gz while the hard limit stays 1.5 MB (ADR-023 decision 6, changed only by a new ADR); "View as table" and styling add no data fetch, so the 5 MB per-interaction rule is unchanged.

## Acceptance criteria (new; test method)
- AC-UX-1 Contrast. A repository script (pure Node, no dependency) parses the tokens of both themes and checks: every text/surface pair at least 4.5:1, every bin ink on its fill at least 4.5:1, every border, glyph, focus and chart colour at least 3:1 against its adjacent surface, with unrounded ratios. Playwright additionally samples computed colours of rendered elements in both `colorScheme` emulations and applies the same function. Fails the build on any pair below the limit.
- AC-UX-2 Non-colour distinguishability. For every row of the state table, a fixture cell renders with a unique pair (visible text code, shape/pattern attribute); a Playwright test renders all states under a CSS `grayscale(1)` filter and asserts the pairwise-distinct signatures through DOM attributes and distinct screenshot hashes; a deuteranopia-filter screenshot is attached as a review artifact (not an assertion).
- AC-UX-3 Themes. All pages load without error and pass AC-UX-1 sampling under `prefers-color-scheme` light and dark; the data encodings keep "more intense = higher percentile" in both; no hard-coded colour literal outside `style.css` (static scan of `src/`).
- AC-UX-4 Keyboard and focus. Playwright tab traversal on V1-V5: every control reachable, no trap, skip link works, focus indicator computed width at least 2 px and 3:1, and the focused element's bounding box is not covered by the sticky header (2.4.11); targets at least 24 x 24 CSS px (2.5.8); every function has a non-drag alternative.
- AC-UX-5 Semantics. Every `<table>` has a caption and `th scope`; each heatmap cell has text content; sortable headers are buttons with `aria-sort`; every chart has `role="img"`, a non-empty label naming indicator, countries, range and the stored latest value, and a "View as table" disclosure whose table matches the plotted points; headings are ordered with one `h1`.
- AC-UX-6 Responsive. At 320, 390, 768, 1280 and 1920 CSS px: no page-level horizontal scroll (scrolling only inside table containers), no clipped text, no overlap of controls; screenshots saved as artifacts. Text-spacing override (1.4.12) produces no clipped text.
- AC-UX-7 Visual review. Per-view screenshots in light, dark and print emulation are uploaded as CI artifacts for human review. A pixel-diff baseline is NOT asserted (cross-OS font rendering makes it flaky and `@playwright/test` is not approved) unless the user approves that dependency (Q8).
- AC-UX-8 States. Playwright routes simulate a missing file, a schema-invalid file, an unknown manifest major and a stale `known_cutoff`: each gives the specified `role="alert"` block or banner with the confirmed wording and no partial numbers; the empty-group and no-series texts are the confirmed strings; the no-JS notice exists.
- AC-UX-9 Print and preferences. Under print emulation: controls hidden, `<details>` expanded, freshness line, caveat and sources present, no table clipped, `page.pdf()` succeeds; under `reducedMotion: reduce` no transition runs; under `forcedColors: active` the state signatures (text code, border, glyph) remain.
- AC-UX-10 D6 and fidelity. The static scan used for V2-V4 is extended to the new modules (no arithmetic helper, no mean/rank/percentile/composite computation, no banned words); the displayed heatmap numbers and bins for sampled cells equal the published scorecard JSON (extends AC-DASH-3); the landing heatmap has no overall column and no default composite order.
- AC-UX-11 No off-origin, font. `dist/` contains no URL outside the allowed namespaces (AC-NPM-3 scan, extended to CSS); the font file is served same-origin; `site/src/fonts/OFL.txt` exists when a font ships; the licence listing of ADR-024 decision 3 includes it; no `@import` of a remote stylesheet.
- AC-UX-12 Weight and stability. Real `gzip -9` of the landing set (including all domain scorecards if the landing heatmap ships, and the font) at most 600 KB internal target and at most 1.5 MB hard limit; CSS at most 20 KB gz; font file recorded with its size; Cumulative Layout Shift (PerformanceObserver in Chromium) at most 0.1 on V1-V5; one explorer interaction unchanged (at most 5 MB gz).
- AC-UX-13 Copy. `copy.js` strings appear verbatim where required (caveat, "percentile vs all ranked countries", domain-figure label, M18 note, V4 fixed text, "earliest stored version"); "first release" and "first stored release" appear nowhere; judgement words are absent next to percentiles (extends AC-EXP-12).
- AC-UX-14 Manual (recorded in `docs/ops/`). One screen-reader pass (VoiceOver on Safari at minimum) over V1 domain page, V3 and V4; Firefox and Safari visual check (ADR-023 C5); the record states browser versions and findings. Not automatable here.

## Consequences
- Positive: one place for colour, type and state rules; dark and print supported; states readable without colour; the heatmap is accessible by construction; everything is testable with the existing Playwright and node:test setup; no dependency, no off-origin asset, no change to the export contract or to D6.
- Negative: more CSS and a copy module to maintain; the landing heatmap increases the landing payload (estimated, not measured) and is conditional; a hand-rolled contrast script and state tests replace off-the-shelf audit tools (no axe-core), so coverage is narrower than a full audit and the manual check AC-UX-14 matters; no pixel-diff regression test without a new dependency; Inter adds about 90 KB if chosen; two themes double the colour review.
- Risks: Framework's `style` option and its theme variable names are [UNVERIFIED] (docs unreachable this session); whether Framework copies a `.woff2` from `src/` unchanged is [UNVERIFIED]; real-export density (42 rows x about 10 indicators, long country and indicator names) may force abbreviated column headers or a different mobile pattern; the candidate hex values are not yet proven; whether the stored percentile is oriented by `good_dir` is unclear from the spec (Q3); manual accessibility checks depend on the user's time.
- Work created: Stage 0-6 tasks for a later plan; new files `site/src/style.css`, `site/src/lib/copy.js`, optional `site/src/fonts/*`, a contrast script, extended smoke tests; an ADR-024 licence-listing entry for the font; no change to ADR-010/023/024, the export spec or `CLAUDE.md`.
- Reversal: the tokens are variables, so palette or font can change in one file; choosing a chart or component library later needs a new ADR.

## Open questions for the user
- Q1 Font: Inter (about 90 KB, consistent look) or the system stack (0 bytes)? Who subsets the file, or may Stage 0 do it with a tool run outside the repo?
- Q2 Theme: automatic `prefers-color-scheme` only, or also a manual light/dark switch (needs a small script and `localStorage`/cookie-free memory; a switch without storage resets on reload)?
- Q3 Orientation: is the stored `percentile` already oriented so that a higher value always means a higher position in the favourable direction, or is it the plain rank of the transformed value? The design assumes no good/bad meaning and a neutral scale; please confirm or point to the spec text.
- Q4 Display of percentile: keep the stored 0-1 number as today, or show it as 0-100? (x100 is arithmetic on a stored value and would change confirmed wording.)
- Q5 Landing: country x domain heatmap on the landing page (loads every domain scorecard, estimated 250-400 KB gz, not measured) or keep the domain list and put heatmaps on domain pages only?
- Q6 Status: should the pipeline export an overall freshness state so V5 can show one traffic light, or is the per-group list enough? (The browser must not derive it.)
- Q7 Accessibility record: who performs the screen-reader and Firefox/Safari checks (AC-UX-14), and is WCAG 2.2 AA the right committed target?
- Q8 Tooling: allow, via separate ADRs, `axe-core` for automated audits and `@playwright/test` for screenshot baselines? Default is no.
- Q9 Mock-ups: do you want Figma mock-ups of the heatmap and state vocabulary reviewed before Stage 1, or review the Stage 1 build directly?
- Q10 New wording: confirm the new strings listed in brief section 11 (bin labels, state codes, "ahead" tag, loading/error sentences, print footer).
- Q11 Timing: Stage 0 waits for a real export; should the Eurostat `TIME_PERIOD` fetch fix come first, or should Stage 0 start on the fixture?
