# Spec: dashboard v2 analytical redesign (Country mode, Compare mode, chart catalogue, display rules)

Labels as in ADR-037: [REPO] read this session; [UNVERIFIED] not checked. Export inventory read from: `docs/specs/dashboard-export-spec.md` (sections 3, 6), `site/src/data/{manifest,meta/*,scorecard/labour}.json` (synthetic fixture, 7 indicators), `docs/ops/dashboard-ux-baseline.md` (e) for the real-export structure (45 entities, 80 indicators; Eurostat-only coverage). The real export itself was not available in the repository on 2026-11-12.

## 1. Conventions
1.1 Stored values only (D6). Allowed in the browser: select, filter, sort by stored field, clip the x-domain, join two stored values on identical keys (entity, period), map a stored value to a position or colour, format. Not allowed: rank, percentile, mean, median, quantile, regression, resampling, unit conversion, differences, growth rates, overall status. The single count exception is the hidden-rows count (ADR-036, widened by ADR-037 decision 4; function named in Amendment 1, A1.4). The one value transform is the display-only rebase of an index series to 100 (section 6.4).
1.2 Files read (names as in the export spec): `meta/entities.json`, `meta/groups.json`, `meta/domains.json`, `meta/indicators.json`, `meta/series.json`, `scorecard/<domain>.json`, `series/<indicator_id>.parquet` (columns: entity_id, series_id, ref_period_start, ref_period_end, frequency, value, value_default_tf, value_yoy, value_status, known_at, load_kind). New files are only those of change requests (section 8) and each is marked.
1.3 Feasibility vocabulary: YES (renders from today's export contract), PARTIAL (renders, with a named limitation), NEEDS (blocked on a named export change or on WEO ingestion). Separately each chart has a coverage note for the Eurostat-only export: the chart is correct but may show few countries; the disclosure of section 7 explains the rest.
1.4 URL hash additions to spec 1.5 and ADR-034: `m` (country|compare), `x` and `y` (indicator ids for C3), `p` (period or period range), `pc` (0|1 percentile layer), `ctx` (0|1 grey context lines), `proj` (0|1 projection layer), `oth` (0|1 include other reference periods), `rb` (base period for rebase, index series only). Unknown values fall back to defaults; defaults produce an empty hash. (Replaced by Amendment 1, A1.3: `m` and `proj` removed, `p` is a single period, `stl` added.)
1.5 Every chart is a card with: title (indicator name, never an id), caption block (section 6.1), the figure, a "View as table" disclosure (same stored rows, unit in every header), the hidden-rows disclosure (section 7), and a no-JS notice inherited from the page. Colour is never the only channel for state or series identity (ADR-025 decision 3).

## 2. Modes and navigation
- Header: Home (dashboard), Country, Compare, Time series (PG-SERIES), Domains, Revisions. A mode switch (two tabs, `aria-current`) sits at the top of the filter bar; switching keeps `c`, `i`, `g`, `p` when meaningful for the target.
- Country mode page: PG-COUNTRY (`/country/<entity_id>`; also reachable by the picker on Home with `m=country`). Compare mode page: PG-COMPARE (`/compare` with `i` indicator or `d` domain) and PG-INDICATOR (`/indicator/<id>`) which is Compare mode with that indicator fixed. (Amended by Amendment 1, A1.3 and A1.7: the mode comes from the route, not from `m`; "Country" without an entity opens a country list page.)
- Home (PG-HOME): the mode switch, the picker, the Browse lists; no chart is required there beyond what ADR-034 provides; Home shows K1 cards when one country is chosen and C2 when an indicator is chosen (reuse, no new component). (Replaced by Amendment 1, A1.7; A1.7 Home is in turn replaced by Amendment 2, A2.3: Home is a dense overview with a KPI strip and four chart panels C2, C1, C6, C4.)

## 3. Country mode chart catalogue

### K1 Latest-value cards with trend
- Question: what is the latest stored value of each indicator for this country, when is it from, and which way has it moved recently?
- Page: PG-COUNTRY, section band per domain.
- Files and fields: `scorecard/<domain>.json` row for the entity: `value`, `ref_period_end`, `value_kind`, `is_stale`, `known_at`, `series_id`, `transform_id`, `transformed_value`; `meta/indicators.json`: `name`, `unit_label`, `frequency_set`, `scale_hint` (CR-18, optional); `meta/series.json`: `frequency`, `seasonal_adjustment`, `source_name`. Trend sparkline: the last stored values of the series. Today: from `series/<indicator>.parquet` (loaded on demand per domain). After CR-16: from the stored array in the scorecard row, no Parquet load.
- Feasibility: PARTIAL. Card without sparkline is YES. Sparkline is YES with on-demand Parquet (weight cost: up to 14 files for agri; measured by AC-V2-40) and NEEDS CR-16 for a landing-weight solution. A numeric delta or arrow is NOT offered (computed; CR-11 not approved). If the series file has `value_yoy` and the indicator is a level, the card may print "y/y" as that stored column labelled as stored (ADR-037 decision 5).
- Axis/unit/frequency: no axis; the sparkline is unlabelled except an accessible name (unit, first and last stored value and period); y range per card; latest point marked (hollow when `value_status` is EST or PROV).
- Missing data: a card is drawn only when `value` is non-null; otherwise the indicator goes to the card's hidden-rows disclosure with the stored reason sentence (ADR-030 decision 5). Stale cards are drawn with the stale marker and the period; staleness is a marker, not a reason to hide, because K1 is a series-currency view.
- Plot marks: none for the number; sparkline is d3 `line` in inline SVG (ADR-034 decision 8, no Plot instance per card).
- AC: AC-V2-10 every card prints indicator name, value, unit, reference period and source; AC-V2-11 no delta, arrow or colour by direction (amended by Amendment 2, A2.4: a neutral delta from a stored value only, never coloured by direction); AC-V2-12 estimate hollow marker; AC-V2-13 empty indicators appear only in the disclosure.
- Tests: unit (card text builder, sparkline accessible name), smoke (card count equals indicators with value; disclosure holds the rest).

### L1 Domain small multiples of lines
- Question: how have all indicators of one domain evolved for this country, each on its own scale?
- Page: PG-COUNTRY, one card per domain (collapsed after the first two), facets in `meta/domains.json` `indicator_ids` order; at most 12 facets per view, then "Show more" in blocks (ADR-034 decision 7).
- Files: `series/<indicator_id>.parquet` filtered to `entity_id`: `ref_period_start`, `value`, `value_status`, `frequency`, `series_id`; `meta/indicators.json` name and `unit_label`; `meta/series.json` for unit, seasonal adjustment.
- Feasibility: YES. Loads one Parquet per indicator in the domain on demand (first interaction rule 5 MB gzipped; AC-V2-40). CR-20 (per-entity bundle) only if measured too heavy.
- Axis/unit/frequency: each facet has its own y axis in its own unit; facets never share y; the x domain is shared across facets of the card (the Period control) so annual and monthly panels align in time; no resampling: a monthly panel plots monthly points, an annual panel annual points; the frequency is printed in each facet caption. An indicator with more than one frequency in `frequency_set` uses the Frequency control, default the frequency of the country's series; if the country has several, one facet per frequency.
- Missing data: a facet with no stored value for this country is not drawn and is listed in the card's disclosure. A series with gaps (null `value`, `MISS`) draws a broken line (no interpolation). Series starting later than the x-domain simply start later.
- Plot marks: `Plot.lineY` per facet (via `fx`/`fy` facet or one small Plot per indicator; implementation chooses, tests do not depend), `Plot.dot` for the last point and for EST/PROV points hollow, `Plot.ruleY` at 0 when the plotted range crosses 0, `Plot.tip` with `Plot.pointer` for hover [UNVERIFIED in 0.6.18 here; ADR-030 decision 6 already flags this].
- AC: AC-V2-14 no facet shares a y axis with another indicator; AC-V2-15 each facet title is the indicator name and its caption block prints unit, frequency, seasonal adjustment, source; AC-V2-16 at most 12 facets before "Show more"; AC-V2-17 gaps are not bridged; AC-V2-18 table alternative lists the same rows.
- Tests: unit (facet selection and ordering, gap handling), smoke (axis labels carry unit), static scan (no `d3.mean|median|quantile|sum` in the chart modules, extending AC-RD-50).

### L2 One indicator, one country, long line (series reader with context)
- Question: what is the history of one indicator for this country, including estimate marks, revisions and (later) the IMF projection?
- Page: PG-COUNTRY (expanded facet) and PG-SERIES; this is the existing series reader generalised.
- Files: as L1 plus `revisions/<indicator>.parquet` link; projection layer later: `projection/<indicator_id>.json` (ADR-032 decision 4b).
- Feasibility: YES for observed; NEEDS ADR-032 plus WEO ingestion for the projection layer.
- Axis rules: one y axis in the indicator unit; for an index series the rebase control (section 6.4) is available; with the projection layer on, rebase is disabled (ADR-032 6a). (Amended by Amendment 1, A1.5: before CR-18 no rebase is inferred from `unit_label`.)
- Marks: `lineY` solid for OBS, `dot` hollow circle for EST/PROV, `ruleX` at the last observed period when the projection layer is on, dashed `lineY` with diamond `dot` for PROJ, `tip`.
- AC: AC-V2-19 projection layer off by default, Level only, dashed + diamond + rule + edition label + attribution (reuses AC-PROJ-5, 6, 7, 8); AC-V2-20 observed and projected points never share a line.
- Tests: reuse AC-PROJ-1..10 once ADR-032 is approved; before that, unit test that the layer control is absent.

### P1 Position against peers
- Question: where does this country stand on indicator Y relative to the other countries, now (strip) and over time (band)?
- Page: PG-COUNTRY, per indicator in an expanded facet or a dedicated "Peers" band.
- P1a strip plot, now: all countries' stored latest values of one indicator on one horizontal axis, the chosen country highlighted, aggregates as reference ticks. Files: `scorecard/<domain>.json` rows of the indicator (`value`, `ref_period_end`, `alignment`, `is_stale`); `meta/entities.json`. Feasibility: YES (but values from a single aligned reference period only; rows outside it are hidden by default and listed, section 7). No median or quartile is drawn (not stored). Marks: `Plot.dot` (x = value, y jittered by a fixed stored order, not random), `Plot.text` label for the chosen country, `Plot.ruleX` none. Coverage: with the Eurostat-only export only the countries with an aligned stored value appear (3 of 42 in the ranked domain, per the baseline). (Jitter order fixed by Amendment 1, A1.7.)
- P1b band over time: line of the country plus a shaded band p25 to p75 and a median line of the peer group per period. Files: NEW `peer_stats/<indicator_id>.json` (CR-17): rows `{group_id, ref_period_end, frequency, n, min, p25, median, p75, max}` computed in Python at export from the same panel the percentile uses, stored values, unit from `meta/indicators.json`. Feasibility: NEEDS CR-17; also needs n at least a configured minimum (stored `n`; the band is drawn only where `n` is at least the value the user sets, Q6).
- Marks (P1b): `Plot.areaY` with `y1 = p25`, `y2 = p75`, `Plot.lineY` for median, `Plot.lineY` for the country. The legend names the group and the stored `n` at the latest period.
- AC: AC-V2-21 P1a draws only stored values and no summary statistic; AC-V2-22 P1b band comes only from `peer_stats`; no `d3.quantile`/`median` in browser code (static scan); AC-V2-23 the band declares group and n; AC-V2-24 a period with n below the threshold draws no band.
- Tests: unit (strip selection; band file schema), scan.

### T1 Latest values table
- Existing indicator table (ADR-034 decision 8, spec C-CTRY-2), grouped by domain: indicator, value+unit, reference period, state sentence, source; the percentile column and bin chip appear only with `pc=1`. Feasibility: YES. AC-V2-25: percentile column absent by default; AC-V2-26 orientation sentence present iff the layer is on.

## 4. Compare mode chart catalogue

### C1 Multi-country line
- Question: how has indicator Y moved over time in these countries?
- Page: PG-COMPARE / PG-INDICATOR.
- Files: `series/<indicator_id>.parquet` (all entities in one file), `meta/entities.json`, `meta/groups.json`, `meta/series.json`.
- Feasibility: YES. One Parquet file for all countries. Coverage: depends on data; the Eurostat-only export has M09 for the countries loaded.
- Rules: up to 5 highlighted countries (cap, ADR-025 decision 6) coloured and directly labelled; optional context lines for the other countries in a neutral light grey, off by default (`ctx=1`); no legend of 40 entries; hover tip names the country. One y axis, one unit: if `meta/series.json` shows more than one `unit_code`, price basis or currency basis among the chosen countries the chart is blocked with a stored-field message, and the user is offered the share of countries with a single basis (selection of stored values, no conversion). Seasonal adjustment mixed: not blocked, but each tip row and the caption mark "SA" or "NSA" and the caption says the chart mixes them (stored fields). Mixed frequencies for one indicator: Frequency control selects one; no resampling. (The blocking field list is corrected by Amendment 1, A1.6.)
- Index series: optional rebase to 100 at a common base period (section 6.4); otherwise levels. Aggregates (EU27, EA) are drawn dashed-grey reference lines when selected.
- Missing: a country with no value in the x-domain is not drawn and goes to the disclosure.
- Marks: `Plot.lineY` with `z` entity, `Plot.text` end labels (`Plot.selectLast`), `Plot.ruleY` at 0 if crossed, `Plot.tip`+`Plot.pointer`; projection layer as L2 for annual Level indicators with ADR-032.
- AC: AC-V2-30 at most 5 coloured lines; AC-V2-31 blocked on incompatible unit/basis with message; AC-V2-32 no rebase of a non-index or of a projected series; AC-V2-33 every end label carries the unit once in the axis title; AC-V2-34 table alternative.
- Tests: unit (compatibility check on fixture series with two unit codes), smoke.

### C2 Ranked bar of the latest aligned period
- Question: which countries are highest or lowest on indicator Y in the latest comparable period?
- Files: `scorecard/<domain>.json` (`value`, `ref_period_end`, `alignment`, `is_stale`, `rank_reference_period` from `alignment[]`), `meta/*`.
- Feasibility: YES. Replaces the ADR-034 ranked card; the sort is by stored `value` (default), A-Z or percentile (percentile option only with `pc=1`).
- Rules: horizontal bars, zero baseline, neutral fill, one unit (blocked as C1 if units differ), the reference period of the chart printed as the caption (`rank_reference_period`); only rows aligned to it are drawn; others in the disclosure unless `oth=1`, when they are drawn hollow with their own period in the label. Aggregates pinned under the countries as reference rows. No average row.
- Percentile layer (`pc=1`): a second column with the stored percentile number and bin chip; bar fill remains neutral.
- Marks: `Plot.barX`, `Plot.text`, `Plot.ruleX` at 0.
- AC: AC-V2-35 bars start at 0; AC-V2-36 only rows of the printed reference period are drawn by default; AC-V2-37 percentile hidden by default; AC-V2-38 no Total or mean row.
- Tests: unit (row selection by alignment), smoke.

### C3 Scatter of two indicators
- Question: do countries that are high on X tend to be high or low on Y, in the same period?
- Files: `series/<x>.parquet` and `series/<y>.parquet`; `meta/indicators.json`, `meta/series.json`.
- Feasibility: PARTIAL. YES technically (two Parquet loads, join on entity and period). Constraint: both indicators must have the same stored frequency (otherwise blocked, no resampling), and for annual indicators a chosen year, for monthly/quarterly a chosen period; points are the countries that have both values in exactly that period. Cross-source pairs on the Eurostat-only export may have no overlap (labour M09 with HICP P01 are both monthly Eurostat and can overlap); the card says so through the disclosure. After WEO ingestion annual pairs (A03 growth vs A05 debt, A04 balance vs A05) become possible for up to 42 countries.
- Axes: x indicator and its unit on x, y indicator and its unit on y, each titled with unit; both start at the data extent (no forced zero), a zero rule drawn when a range crosses zero; no regression or trend line, no correlation number (computed); no point size or colour encoding a third variable in phase 1; labels for the highlighted countries only (cap 8) to avoid overplotting; aggregates excluded by default.
- Period control: `p` single period from the stored common periods (the set intersection is a selection). Default: the latest period for which both have at least 5 stored points, else the latest common period; "at least 5" is a threshold the user sets (Q6).
- Missing: countries without both values are listed in the disclosure with the reason ("no value for <indicator>").
- Marks: `Plot.dot`, `Plot.text` labels, `Plot.ruleX|ruleY` at 0, `Plot.tip`.
- AC: AC-V2-41 blocked when frequencies differ, with the stored reason; AC-V2-42 only points with both values in the chosen period; AC-V2-43 both axis titles carry unit; AC-V2-44 no regression/correlation (scan); AC-V2-45 the table lists country, x, y with units and period.
- Tests: unit (common-period join, frequency block), smoke.

### C4 Heatmap country x period
- Question: which countries had high or low values of indicator Y in which periods (a time-by-country map of one indicator)?
- Files: `series/<indicator_id>.parquet`, `meta/*`.
- Feasibility: YES for annual and quarterly indicators; PARTIAL for monthly (many columns): window rule below. Coverage depends on the data; WEO annual series from 1991 give the best case (42 rows x about 35 columns).
- Rules: rows are countries sorted by the latest stored value (default) or A-Z; columns periods of one frequency (Frequency control); window: annual up to 35 columns, quarterly up to 40, monthly up to 36 (the Period control chooses the window; no resampling). Cell colour = stored value through a sequential single-hue scale for non-negative ranges; a diverging scale with the midpoint at 0 when the displayed range crosses 0 (growth, balance). The scale domain is the displayed stored min and max (display scaling, stated in the caption: "colour scale: min to max of the cells shown"); no clipping, no winsorising. Cells without a value are blank with a hatch pattern (not white, not zero), and are not counted. A numeric table alternative exists; cell text appears when the cell width permits. Unit and period printed; projections never appear (excluded, ADR-037). (Stale rows and the `stl` toggle: Amendment 1, A1.1.)
- Marks: `Plot.cell` with `x` period, `y` entity; `Plot.text` optional; legend via `Plot.legend` or a custom d3 gradient bar with min and max labels.
- AC: AC-V2-46 colour scale declared in the caption; AC-V2-47 diverging scale only when the range crosses 0 and the midpoint is 0; AC-V2-48 blank cells hatched, never coloured as zero; AC-V2-49 window cap per frequency; AC-V2-50 no PROJ cell (scan on the module's inputs).
- Tests: unit (scale type selection, window), smoke, accessibility (table alternative present).

It is percentile-based; it appears only on `domain/<id>` and is not part of the default Compare view. AC-V2-51 (amended, decided by the user 2026-11-13, confirmed in chat): C5 is rendered on no page unless `pc=1`, including `domain/<id>`; hidden by default. (Placement clarified by Amendment 1, A1.7: secondary block.)

### T2 Indicator table with sparkline (kept)
- ADR-034 decision 8 unchanged; percentile column opt-in.

### C6 Projection ranking (phase 3, NOT specified in full) [renamed C7 by Amendment 2, A2.2; the name C6 now belongs to the choropleth map specified in section 13]

## 6. Economically correct display rules (apply to every chart)
6.1 Caption block (data fields from stored files, no prose): indicator name, unit text (`unit_label`, or series-level `unit_code` with `unit_mult` when CR-19), frequency (names: annual, quarterly, monthly), seasonal adjustment (SA, NSA, not applicable as stored), reference period or range, source name(s), latest-vintage line "latest vintage as of <known_cutoff>" and `known_at` in the table, estimate/provisional/projection marks explained by legend text codes. AC-V2-70: every chart's caption block contains these fields or the stored "not stated" marker. (CR-19 field names: Amendment 1, A1.6.)
6.2 One axis, one unit. Series are plotted together only if `unit_code`, `unit_mult`, `price_basis`, `currency_basis`, `flow_basis` and `base_period` (for indices) are equal; otherwise blocked with a stored-field message. Dual axes and per-chart units mixed in one panel do not exist. Small multiples carry separate axes. AC-V2-71. (Field list corrected by Amendment 1, A1.6.)
6.3 Form of the quantity. A series is plotted as stored: level, rate, index, or change (the percent-change series, e.g. "% y/y", is a change series; its values are not differenced or compounded). The chart title and axis title state the form from `unit_label` and `scale_hint` (CR-18; until it exists the form is read from `unit_label` text only and no inference is made, so the title shows `unit_label` verbatim). Bars start at zero; lines show a zero rule when crossing zero; no log scale; no truncated bar axes. AC-V2-72.
6.4 Display-only rebase (the one approved transform, ADR-030 decision 8). Allowed only for indicators with an index form (stored `unit_label` "index" and a stored `base_period`), only on L2 and C1, only for Level, only to a base period every plotted series has a value in; the caption states "Index, <period> = 100, rebased for display; stored values unchanged." Projections are not rebased (layer disabled). AC-V2-73: rebase absent for non-index indicators; AC-V2-74: statement present whenever the rebase is active. This is a transformation in the sense of the IMF terms if applied to WEO values; WEO series are not index-type in the mapped set (A02 to A05 are percentages), so the rebase never applies to them. (Gating replaced by Amendment 1, A1.5: no reading of `unit_label` text; rebase is off until `scale_hint = index` (CR-18) is exported, no interim marker.)
6.5 Frequency. One frequency per panel; no resampling; mixed-frequency panels (country mode) align on a shared time axis; monthly, quarterly and annual points are not connected to each other. A tip prints the period label per stored frequency (2026-03, 2026 Q1, 2026). AC-V2-75.
6.6 Seasonal adjustment. Stored `seasonal_adjustment` is shown in the caption and in each tip. Mixing SA and NSA in one compare chart marks it in the caption; a year-over-year series is allowed on NSA (no inference). AC-V2-76.
6.7 Reference period and vintage. Snapshot charts print the reference period; if rows differ in period they follow the alignment rule (section 3, C2). Series charts print the cut-off line. Revisions are not drawn on the lines (the series file is the latest vintage); each chart links to the revisions page of the indicator. AC-V2-77.
6.8 Observed, estimate and projection. OBS: solid line, filled markers on points when sparse; EST/PROV: hollow circle; PROJ: dashed, diamond, vertical rule at the last observed period, own legend text code, edition label and attribution (ADR-032); a projection is never drawn into snapshot charts. For WEO-fed series the observed/projected boundary is whatever the stored `value_status` says per row (the WEO CSV carries LATEST_ACTUAL_ANNUAL_DATA per country, and in at least the Syria row read [REPO] the last actual year is 2009 while values run to 2025, so the boundary differs by country and is not a global year). AC-V2-78.
6.9 Naming and numbers. Indicator names from `meta/indicators.json`; number format follows `published_precision` (display hint, no rounding of stored value in data files); thousands separators locale-independent; units text exactly as stored. AC-V2-79.

## 7. Missing data and disclosure (ADR-036 extended)
7.1 Reason categories (stored fields only): `no series` (no series listed for the pair in `meta/series.json`), `no value` (series listed, no stored value in the plotted period), `stale` (`is_stale` true, snapshot charts only), `other period` (`alignment` unaligned, snapshot charts only), `not ranked` (only where ranking is shown). Order of the list: reason, then name A-Z. (Regrouped into four categories by Amendment 1, A1.4.)
7.2 One `<details class="mm-hidden-rows">` per card under the title, same markup, `role="status"` wrapper, strings from `copy.js` (DRAFT; the sentence for coverage hiding is new: "<n> rows not drawn (no value, other period or stale)"; wording is the user's to confirm). N is the length of the hidden array (ADR-036 I1). Nothing is rendered when N is 0 (I7). (Sentence replaced by Amendment 1, A1.4.)
7.3 Hidden rows are never dropped from the table alternative: the table shows every row, the hidden ones after the others with the state sentence.
7.4 AC-V2-80 the disclosure count equals the length of its list for every chart; AC-V2-81 a snapshot chart with only stale rows renders the empty-card message "No aligned values for this selection" (DRAFT) plus the disclosure, never an empty axis; AC-V2-82 time-series charts never hide stale rows; AC-V2-83 no `n/a` literal appears alone. (AC-V2-80 and AC-V2-82 amended by Amendment 1.)
