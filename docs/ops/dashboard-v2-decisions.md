# Dashboard v2 implementation decisions (log)

Choices made while implementing the v2 analytical plan where the spec left them open. Chosen for analytical correctness: stored values only, no client compute.

## V2: hash extension (2026-11-13)
- Order confirmed: existing `hash.js` order was `i, c, g, d, f, from, to`; new keys appended as `x, y, p, pc, ctx, oth, stl, rb`. No mismatch with A1.3 (which marked it unverified).
- `m` and `proj` are ignored silently (no `note`): they are removed keys, so old links should not raise a warning. Not parsed, not written.
- State shape: `pc, ctx, oth, stl` are booleans (default `false`); `x, y, p, rb` are string or `null`. Flags accept only `0` or `1`; `pc=0` is valid and equals the default (no note, serializes to nothing). Duplicated keys: first occurrence wins, note set (as for existing keys).
- `p` format check is the regex for `YYYY`, `YYYY-Qn`, `YYYY-MM` (month 01..12). Membership in the stored common periods is checked only when the caller passes `known.periods`; without it only the format is checked. The serializer re-validates format, so a malformed `p` or `rb` in a state is never written.
- `rb` uses the same period format as `p`; `known.basePeriods` optionally restricts it to stored base periods. Gating `rb` to index series stays with the caller (A1.5, CR-18); the hash module only validates shape.
- `x`, `y` are validated like `i` against `known.indicators`.
- `carry.js`: added `carryHashFor(hash, target)` and `carryHrefFor`, a pure string filter by key. Country keeps `i, c, g, d, f, from, to, p, pc`; Compare keeps all keys. `g` is kept for Country after the Opus review of Group A (spec 5.3 lists Group for P1; first version dropped it); compare-only keys (`x, y, ctx, oth, stl, rb`) are dropped. `installCarry` is unchanged and still carries the whole hash (existing behaviour, baseline unchanged).

## V3: compatibility module (2026-11-13)
- `checkCompatible(seriesList)` returns `{status: "allowed"|"blocked"|"marked", blocked: [{field, values, absent_for_some}], marked: [...], skipped: [fields]}`. Series objects are the stored series metadata rows (`meta/series.json`).
- "Absent" means key missing, undefined or null. The fixture stores `base_period: null` for non-index series, so null for all is skipped, and null mixed with a value blocks (as for any field present for some only).
- Blocking fields: `unit_code, unit_mult, price_basis, flow_basis, base_period, frequency`. Marking: `seasonal_adjustment`. A frequency mismatch is reported in `blocked` with the other fields (all reasons listed, not first-only). Fewer than two series: allowed, nothing skipped.
- Skipped fields are reported only when the selection has two or more series. `currency_basis`, `unit_label`, `unit_text` are never read (test scans the source).
- `compat` appended to LAYOUT_MODULES in `tests/prose-scan.test.mjs` (new-module rule AC-DB-32); the module holds no prose literals.

## V5: caption block (2026-11-13)
- `site/src/lib/caption.js`: `buildCaption({indicator, series, range, knownCutoff, statuses})` returns `{fields, legend}`; fixed field order indicator, unit, frequency, seasonal, period, source, vintage. `captionTitle(indicator)` prints the stored `unit_label` verbatim and reads it only through `units.js` (AC-V2-72).
- The "not stated" marker did not exist in the code base; it is `DRAFT_NOT_STATED = "not stated"` in `copy.js` (DRAFT, user confirms wording). It is printed for every absent stored field, for a field absent from some of the plotted series (shown next to the stored values, not hidden), and for a period range of mixed frequencies (no single period label is invented).
- Several distinct stored values are all printed, A to Z (for example `NSA, SA` when a selection mixes SA and NSA: that is the spec 6.6 caption mark; nothing is inferred). Sources are the stored `source_name` values, once each.
- Unit text: the indicator's stored `unit_label`; when the indicator has none, the stored `unit_code` of each plotted series, with the stored `unit_mult` note ("values in EUR x 10^6"). No `unit_text` / CR-19 field is read (not exported).
- Seasonal adjustment: stored `SA` and `NSA` as stored; a stored "n/a" is printed as "not applicable" (AC-V2-83: n/a never alone); any other stored string is printed as stored.
- Legend codes: only EST and PROV, only when the caller passes those `value_status` codes as present in the plot. PROJ is not offered (phase 3).
- Vintage line: `latest vintage as of <UTC date of manifest known_cutoff>` via the existing `utcDate`.

## V4: hidden-rows model (2026-11-13)
- `splitByCoverage(rows, context)` returns `{drawn, hidden}`; `hidden` is a list of `{row, reason}` so the stored row is never mutated and each element carries its reason as ADR-037 A1.4 requires. `countHiddenRowsByReason(hidden)` returns `{total, no_data, stale, other_period, other}`; it is the single whitelisted count and replaced `countPeriodHiddenRows` (removed; `rank-model.js` and `table-card.js` now call `splitByCoverage` with Period only, so their behaviour and the existing "N rows hidden by the period filter" sentence are unchanged). `splitByPeriod` stays; both share one Period rule.
- Coverage checks are opt-in context keys (`requireValue`, `hideStale`, `referencePeriod`, `includeOtherPeriods`, `isOther`, plus `hasSeries`/`hasValue` accessors). With none of them the result is the Period split alone, so tables that keep rows without a value (ADR-030) are not affected. Staleness hides only when the caller sets `hideStale` (C2, C3, P1 strip, C4 with `stl=0`); L1, L2, C1 and K1 leave it off (AC-V2-82).
- `no_data` = no stored finite value (a stored 0 is a value), or `hasSeries(row) === false`. `stale` = stored `is_stale === true`. `other_period` = outside the Period years, or stored `alignment === "unaligned"`, or the stored period of the row differs from the stated `referencePeriod` (identical stored strings are compared, no date parsing; a row with no stored period against a stated reference is `other_period`). `other` = the caller's `isOther(row)` on a stored field. Precedence no_data, stale, other_period, other; an unknown reason is counted as `other` so every row is in exactly one category and X + Y + Z + W = total.
- `site/src/lib/hidden-rows.js`: `hiddenRowsModel`, `hiddenRowsDisclosure` (the `<details class="mm-hidden-rows">`, or "" at N = 0), `hiddenRowsRegion` (the persistent `role="status"` wrapper, empty at N = 0 so changes are announced, ADR-036 I5). The list is ordered by reason precedence then label A to Z (ties by id) using `sortRows` (no comparator arithmetic). Row link is optional (`href` accessor, `data-carry`), no value, percentile or chip is printed.
- List item text `DRAFT_HIDDEN_LIST_ITEM`: `<label>: <reason label>; latest value <period or not stated>; <stored reason sentence or not stated>`. The stored reason sentence is read from `row.reasonSentence` or `row.state.sentence` (the `missing.js` sentence); the card builders supply it. Summary template `DRAFT_HIDDEN_SUMMARY` follows A1.4 exactly (singular "1 row hidden: 1 no data"); plural variants per language arrive in V45.
- Scan changes: the single whitelisted tally line is `counts.total += 1; ...` in `filter-model.js` (rule "compound assignment or increment"); a second tally anywhere else fails (seeded). The label scan exempts only the exact `total` field reads of that result (`counts.total`, `{total: 0`, `countHiddenRowsByReason(...).total`); any other "total" still fails. The spec mandates the field name `total`.
- Finding for the reviewer: the existing `DRAFT_HIDDEN_ROWS` (Period-only sentence) is still used by the pre-v2 C-RANK and C-TABLE cards; ADR-036 Amendment 1 supersedes it "on the cards ADR-037 governs", so those two cards were not switched to the new sentence here (that is for the card tasks V19 / V15 that rebuild them).

### Choices made where the spec left room
- K1 stale (E-3, user-confirmed): a stale card is drawn with the square marker and "stale, <period>"; `k1Model` calls `splitByCoverage` with `requireValue` only (no `hideStale`), so the only K1 hide reason is `no_data`. `oth` and Period do not apply to K1.
- K1 has no delta: the scorecard cell stores no delta and no `value_yoy`; the card prints no delta element, arrow, direction word or direction colour (AC-V2-11, 125 absence part). The "y/y (stored)" line is not built (A2.4: needs CR-6 or CR-11).
- L1 panels (V12): one `Plot.plot` per panel, never a Plot facet (V1 finding: facets share one y scale). One panel per stored series of the pair, so an indicator with two stored frequencies has two panels. Stale for a panel is the scorecard cell's `is_stale` for that cell's series (a cell that names no series applies to every panel of the indicator). The first two domain cards are open; the others open by their summary. A series file is read when a card is open and a panel needs it, after the page `load` event (`country-page.js` `flush`), through the shared 5 MB guarded `loadSeries`; each indicator file is read at most once per page. A panel whose file holds no stored value, and an indicator the pair has no series for, are one `no_data` disclosure per card. A file that cannot be read is stated per panel (`DRAFT_SERIES_UNREADABLE`), not counted as hidden.
- Shared x domain: the Period years when set, else the manifest's stored bounds (`periodBounds`): a stored value, not derived from the points. Stored points outside the Period are not drawn.
- "Show more" (12 panels, then the next 12): the shown panels are a list of keys (`l1Reveal`), so the next block is a list selection and no counter exists (the AC-UX-10 scan allows no new increment).
- L2 (V13): the Expand button of a panel opens `l2Block` plus P1a for the same indicator under the card's grid; a second activation collapses it. The revisions link goes to `../revisions` (the page lists revisions by indicator; it has no per-indicator anchor).
- P1a (V14): rows are every entity of the comparison set (countries, aggregates as reference ticks, the focus country if outside the Group). Selection is one `splitByCoverage`: value required, stale hidden, only the scorecard's stored `rank_reference_period` drawn; a scorecard that states none draws nothing and says so (`DRAFT_P1A_NO_REFERENCE`; every row is then another period, drawn only with `oth=1`). `oth=1` draws other-period rows hollow with their own period in the tip; stale rows stay hidden. Slots: the y scale is a point scale whose domain is the ascending code-point order of the drawn countries' `entity_id`; no jitter, no modulo, no Math. Height is fixed. The strip has no summary mark.
- T1 (V15): without the percentile layer the "percentile vs all ranked countries" column is replaced by a State column that prints the stored currency state (stale, ahead, lagging, unaligned, inherited) as code, glyph and sentence; the percentile column and chip, the domain-figure tile and the percentile strip appear with `pc=1`. (Superseded in the fix pass: the caveat is always printed once per page; the orientation sentence follows `pc` alone, see D3 and F2 below.)

It is a page control, not yet part of `filter-bar.js`; V17 may fold it into the Compare controls.
